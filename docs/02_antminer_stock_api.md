# Antminer Stock API Reference (Заводская прошивка)

**Основной порт управления:** `80` (HTTP CGI-скрипты)
**Порт диагностики (контрольная плата):** `6060`
**Авторизация:** HTTP Digest Auth / Basic Auth (По умолчанию логин/пароль: `root`:`root`)

В отличие от кастомных прошивок (Vnish, Braiins), стоковая прошивка Bitmain не имеет единого REST API. Управление происходит через имитацию действий пользователя в веб-интерфейсе (вызов `.cgi` скриптов).

## Типы прошивок (Profiles)

| Профиль | Описание | Определение |
|---------|----------|-------------|
| **Modern** | Стоковые прошивки для новых S-серий (S19, S21+). Требуют строковые/числовые ключи с префиксом `bitmain-`. | Наличие ключа `bitmain-work-mode` в веб-конфиге. |
| **Legacy** | Стоковые прошивки для D-серий (D9, D7). Требуют числовые ключи без префикса. | Наличие ключа `miner-mode` в веб-конфиге. |
| **VNish** | Кастомная прошивка (не сток), имеет собственный REST API `/api/v1/`. | Наличие ответа на `/api/v1/info` или маркер `vnish` в дампе 4028. |
| **PitBit** | Кастомная прошивка (не сток). Работает во многом как Legacy/Modern, но имеет свои особенности. | Маркер `incm` или `pitbit` в дампе 4028. |

## Поддерживаемые модели и версии

**SHA-256 (BTC):**
- S-серия: S9, S11, S15, S17, S19, S19 Pro, S19j, S21, S21 Pro, S21j
- T-серия: T9, T11, T15, T17, T19, T21
- Примечание: Все S21/T21 используют `miner-mode` вместо `bitmain-work-mode` (в старых ревизиях) или `bitmain-work-mode` (в новых).

**X11 (Dash):**
- D-серия: D3, D5, D7, D9
- ⚠️ **Внимание:** D9 использует `miner-mode` (число), а не `bitmain-work-mode` (строка)

**Scrypt (Litecoin):**
- L-серия: L3, L7, L9

**Equihash (ZEC):**
- Z-серия: Z9, Z11, Z15

**Другие:**
- E-серия: E3, E9
- K-серия: K5, K7, KA3
- KS-серия: KS3, KS5

## 1. Управление подсветкой (Поиск асика)
В новых версиях стоковой прошивки скрипт управления LED строго требует передачи данных в формате **JSON**.
* **Эндпоинт:** `POST /cgi-bin/blink.cgi`
* **Заголовки:** `Content-Type: application/json`
* **Payload (Включить):** `{"blink": true}`
* **Payload (Выключить):** `{"blink": false}`
* **Успешный ответ:** `{"code":"B000"}`

## 2. Перезагрузка (Reboot)
Самый надежный способ перезагрузить стоковый Antminer с корректным сохранением логов и остановкой процессов.
* **Эндпоинт:** `GET /cgi-bin/reboot.cgi`
* **Успешный ответ:** HTTP 200 OK. Асик уйдет в ребут через 5-15 секунд.

## 3. Режим работы (Сон / Майнинг)
У Bitmain нет отдельной кнопки "Сон" (Suspend). Перевод устройства в спящий режим осуществляется путем изменения конфигурации асика.

**⚠️ ТАБЛИЦА КЛЮЧЕЙ ПО МОДЕЛЯМ (PROFILES):**

| Профиль | Поле режима | Тип значения | Поле частоты | Тип значения частоты |
|---------|-------------|--------------|--------------|----------------------|
| **Modern** (S19, S21+) | `bitmain-work-mode` | `0` / `1` (int) | `bitmain-freq-level` | `100` (int) |
| **Legacy** (D9, D7) | `miner-mode` | `0` / `1` (int) | `freq-level` | `""` (пустая строка) |

**Правильный алгоритм (работает для всех версий):**
1. **Получить текущий конфиг:** `GET /cgi-bin/get_miner_conf.cgi`
2. **Проверить оба параметра в JSON:**
   - Если есть `"bitmain-work-mode"` → обновить его на число `1` (Сон) или `0` (Работа) (Modern)
   - Если есть `"miner-mode"` → обновить его на число `1` (Сон) или `0` (Работа) (Legacy)
3. **Отправить обновленный конфиг:** `POST /cgi-bin/set_miner_conf.cgi` с полным телом JSON
4. **Верификация (NEW):** Снова получить `GET /cgi-bin/get_miner_conf.cgi` и убедиться, что параметр реально изменился.

**Пример запроса для D9 (Legacy профиль с miner-mode):**
```http
POST /cgi-bin/set_miner_conf.cgi HTTP/1.1
Content-Type: application/json

{
  "pools": [...],
  "algo": "dash_1766",
  "bitmain-fan-ctrl": false,
  "bitmain-fan-pwm": "100",
  "bitmain-freq": "0",
  "bitmain-voltage": "0",
  "miner-mode": 1,
  "freq-level": ""
}
```

**Значения:**
- `0` = Нормальная работа (полная мощность майнинга)
- `1` = Спящий режим (асик остановлен, кулеры не работают)

## 4. Чтение ошибок (Порт 6060)
Диагностический порт 6060 работает без пароля и отдает системные предупреждения контроллера напрямую.
* **Эндпоинт:** `GET http://<IP>:6060/warning`
* **Формат ответа:** Текст, разделенный точкой с запятой (`;`). 
* **Пример ответа:** `W040;Fan speed is too high;Please check...`

## 5. Определение статуса Сна (Sleep Mode) на новых прошивках
Исторически для определения спящего режима использовался параметр `Mode: 1` или опрос скрытого API на порту `6060`. Однако новые поколения асиков (L9, T21, S21, KS5) изменили это поведение:
* **Ключ Mode:** На новых прошивках значение `Mode: 2` означает **нормальный рабочий режим** (Performance/Normal), а не сон. Использование этого ключа для детекции сна приведет к ложным срабатываниям.
* **Порт 6060:** Скрытый HTTP-сервер на порту 6060 (эндпоинты `/miner_status`, `/readvol`) работает крайне нестабильно, часто обрывает соединение или возвращает `404 Not Found`.

**Золотое правило детекции сна (Порт 4028):**
Самый надежный способ определить, что стоковый Antminer находится в режиме сна — это проверить физические показатели через команду `stats` (CGMiner API). Асик гарантированно спит, если выполняются **все три условия одновременно**:
1. `Hashrate == 0`
2. `fan_num == 0` (Кулеры остановлены)
3. `temp_max == 0` (Датчики температуры отключены)
