# Antminer S21+ Stock: изменение worker третьего слота

Дата: **16 ноября 2026 года**. Устройство в отчёте: `stock-pilot-001`.
Модель — Antminer S21+, Stock **FR-1.15(250422-S21+)**, API **1.0.0**.
Пользователь явно поручил изменить только worker третьего слота: общее имя
`test`, индивидуальная часть по полному IP с подчёркиваниями. Ранее приведённые
URL, worker и пароль уточнены как исходные значения, а не новые настройки.
IP, полные workers, пароли, MAC/SN и тела конфигураций в этот документ не включены.

Применён рабочий путь `prepare_pool_batch` → `execute_pool_batch`, без подмены
модели, версии или backend. Дополнительный ограничитель разрешал один адрес,
известные чтения и единственную запись `/cgi-bin/set_miner_conf.cgi` с точным
подготовленным телом. Перед POST повторно проверен паспорт из system API.
Другие управляющие команды и повтор setter запрещены; intent записан до I/O.

Текущий интерфейс совпал с изученным `/js/miner.c8af43.js`, SHA256:
`3a9adfcbc1e7bb9bfef2970cc423f8a32375ff9a9bf54a5dc6efb788bc094a5a`.

В аудите применяющего запуска: 59 операций — 45 HTTP GET, 13 native-чтений
и 1 POST. Настройки и секреты оставались в памяти; в результатах только
технические метаданные и результаты сравнений. Материалы:
локальный архив проверки — `preparation.json`,
`setter-intent.json`, `result.json`, `request-audit.json`.

Проверка подтверждает изменение worker одного слота на данном точном интерфейсе
и сохранение остальных настроек. Новый URL, новый пароль пула, группа устройств,
сохранение после reboot и фактическое зачисление shares этим прогоном не проверены.
`Alive` не доказывает, что третий слот активен и новый аккаунт принимает shares.

## Восстановление по отдельному поручению пользователя

После первого прогона пользователь попросил вернуть прежнее значение.
В третьем слоте восстановлен исходный worker отдельным новым планом и одной
записью, с теми же ограничениями и свежей проверкой устройства/конфигурации.
Результат — `succeeded`, `accepted_by_api=true`; исходный worker виден и
в сохранённой конфигурации, и в runtime. Все URL и пароли, первые два слота,
все непуловые значения и типы совпали с состоянием до восстановления.
Полная старая конфигурация не воспроизводилась, автоматического отката не было.

Обезличенный результат и отдельный аудит восстановления находятся в локальном архиве проверки.
