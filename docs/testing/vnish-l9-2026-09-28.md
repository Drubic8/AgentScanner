включён. Программа запущена из исходников ASIC Monitor 2.0.3 с текущими исправлениями.
Пароль и Bearer-токены в протокол не включены. Локальный журнал испытаний:
`diagnostics/vnish-l9-acceptance.jsonl`.

## Особенности

- Пробуждение отправлено в 09:01:08 UTC; в 09:02:43 получен положительный
  хешрейт, в 09:03:46 — 17,06 GH/s. Проверка команды за несколько секунд не успела
  дождаться запуска и корректно сохранила `unconfirmed`. Это не отказ ASIC.
- Во время запуска CGMiner API временно не отвечал. Один опрос определил модель
  как `l9` из REST, последующие — как `Antminer L9 (Vnish 1.2.7)` из CGMiner.
  Из-за этого сменилась локальная запись устройства. Защита заблокировала команду
  для старого DeviceId; управляющий запрос при блокировке не отправлялся.
- Испытание продолжено после точного совпадения исходного отпечатка устройства
  с повторно полученным и обновления выбора локальной записи. Проверки перед
  каждой командой оставлены включёнными. Неустойчивый выбор источника идентификации
  при запуске требует отдельного исправления в сканере.
- Добавлена проверка подсветки чтением boolean `find_miner` из `/status`.
  HTTP 200 сам по себе не считается подтверждением состояния. 95 автоматических
  тестов прошли после изменения, включая несовпадающий и отсутствующий статус LED.
- Профиль всего семейства VNish не объявляется аппаратно проверенным на основании
  одного L9. Этот прогон относится к версии 1.2.7; команды на 1.2.6 не испытывались.

## Завершение прогона

Перезагрузка отправлена в 09:05:13 UTC. После краткой недоступности устройство
ответило в 09:05:35 с системным uptime 0:00 (до испытания — 37 дней 22 часа).
В 09:07:07 получено 6,50 GH/s, в 09:07:17 — 11,54 GH/s, состояние mining.
Таким образом, подтверждены сам перезапуск и последующее восстановление добычи.
Финальный опрос в 09:08:04 UTC: Running, **16,92 GH/s**, исходный отпечаток
устройства совпадает.

Сравнение SHA-256 канонического JSON `/settings` до и после испытаний показало
полное совпадение. Значения настроек, пароли и токены в отчёт не записывались.
Перед перезагрузкой подсветка выключена; после неё `/status` вернул
`find_miner=false`. Визуальное подтверждение обоих состояний от пользователя
на момент завершения прогона не получено; API-проверка LED успешна.

Включение подсветки, заблокированное проверкой идентификации, не отправлялось
устройству. После обновления выбора выполнена одна подтверждённая команда
включения. Сон, пробуждение и перезагрузка отправлялись по одному разу;
автоматических повторов управляющих запросов не было. Опубликованный EXE
не пересобирался; изменения обработчика LED находятся в исходниках.
