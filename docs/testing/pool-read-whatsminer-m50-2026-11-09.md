# WhatsMiner M50: чтение пулов RPC 3.0.5

Дата: **9 ноября 2026 года**. Пользователь предоставил адрес конкретного
WhatsMiner для чтения в рамках разработки редактора пулов. Адрес, серийный
номер, MAC, аккаунты, адреса пулов, salt и прочие секреты здесь не сохраняются.
Псевдоним — `pool-whatsminer-001`.

В последнем RPC-прогоне выполнены четыре разрешённых запроса на TCP 4433:
`get.device.info` два раза (включая свежую проверку идентичности),
`get.miner.status` с `param=pools`, `get.miner.setting`. Все вернули `code=0`.
Клиент разрешает только эти чтения и отклоняет `set.*`, `update_pools`,
другие порты и HTTP до отправки. Ограничение проверено отдельным тестом без сети.

Отдельно прочитана только публичная HTTP-точка входа: перенаправление с 80
на HTTPS того же устройства, HTTP 200 и оболочка LuCI. Вход через веб-форму
не выполнялся. Публичная оболочка не доказывает чтение сохранённых паролей.
Клиент этой проверки не сохраняет cookies между HTTP и HTTPS и не передаёт
в веб-интерфейс учётные данные API.

## Что это подтверждает для программы

Существующий RPC3 reader распознаёт модель, прошивку и API и получает три
runtime-пула. В упорядоченном наблюдённом ответе существующая проекция
отображает три записи. Это не доказательство общей схемы нумерации сохранённых
слотов или её неизменности после перезапуска. Алгоритм нумерации не расширялся
по одному наблюдению.

Безопасный отчёт обозначает источник как `whatsminer.rpc_pools`, тип чтения —
`runtime`, а пароль каждого пула — `missing`. Это не пустой пароль и не `x`.
`get.miner.setting` содержит сведения о работе/мощности и суффиксе, но не
предоставляет полной сохранённой конфигурации с паролями пулов.

Команда записи `set.miner.pools` документирована производителем. Отсутствие
паролей в этом ответе не означает невозможность изменения: для новой записи
редактор требует явно задать пароли всех трёх отправляемых слотов. Значения
не подставляются автоматически. Runtime-статистика не доказывает сохранение
паролей или конфигурации после перезапуска. Права конкретной учётной записи
на setter этим чтением не проверялись: включённый API Write сам по себе
их не подтверждает.

**Записей настроек, изменения API Write, управления службой и перезагрузок
не выполнялось.** Вопрос шифрования исследован только офлайн на официальных
материалах: [контракт WhatsMiner](../development/whatsminer_pool_contract.md).

## Доказательства и регрессии

- Последняя обезличенная сводка и журнал только `get.*`:
  локальный архив проверки.
- Дайджест разрешённой структуры:
  `69cb1f1502cd92b0a5607bd84220b9cc1685cbd6858f152b208f812cb81387e9`.
  Значения настроек в этот дайджест не входят.
- [Fixture](../../tests/fixtures/whatsminer_m50_rpc3_pools_read.json) сохраняет
  наблюдённые технические метаданные и типы; **все значения настроек синтетические**.
- [Регрессии](../../tests/test_whatsminer_pool_observed.py) проверяют реальный
  reader на подменённом транспорте, три отображаемые записи, отсутствие паролей,
  отказ при незаданных обязательных значениях и сбор сведений без исполнительного плана.

Отдельная [офлайн-интеграция записи](../../tests/test_whatsminer_pool_integration.py)
проверяет выбранный AES-256-ECB/PKCS7 контракт, передачу явно заданных паролей,
однократный setter и runtime-only подтверждение. Она не добавляет запись
к описанному выше аппаратному прогону. Успех эмулятора не доказывает приём
этого padding конкретной прошивкой или сохранение пароля устройством.

Аппаратная отметка изменения пулов и `verified_commands` не повышаются.
