# Antminer Z11 Stock: чтение старой формы пулов, 09.11.2026

Проверен один выбранный пользователем Antminer Z11, Stock
`Mon Aug 26 13:37:07 CST 2019`, профиль `bitmain.stock`.
Разрешены только запросы чтения. Версия CGMiner API неизвестна:
TCP-опрос не выполнялся. Сборки Z11 апреля/октября 2019 и модели
Z15/Z15e не использовались как замена текущего интерфейса.

Конфигурация и форма прочитаны, но сохранение нетронутых параметров
не доказано. Writer этого интерфейса пока не добавлен; это ограничение
реализации, а не утверждение об отсутствии функции у оборудования.
IP, MAC/SN, значения пулов, workers, настройки и учётные данные
в документ не включены.

## Полученная конфигурация

Прочитаны `/cgi-bin/get_system_info.cgi`, `/cgi-bin/get_miner_conf.cgi`,
`/index.html`, `/cgi-bin/minerConfiguration.cgi` и объявленные локальные
JavaScript. `/miner.html` недоступна. Audit прогона — 11 GET, 0 POST.
JavaScript не исполнялся.

У отдельного GET и встроенного в CGI-страницу `ant_data` совпали все
значения в памяти и полный набор семи верхних ключей:

| Поле | Наблюдённый тип |
| --- | --- |
| `pools` | три объекта со строковыми `url/user/pass` |
| `api-listen`, `api-network`, `bitmain-use-vil` | boolean |
| `api-groups`, `api-allow`, `bitmain-freq` | string |

Все девять полей трёх пулов присутствуют. Три пароля — прочитанные
пустые строки, а не отсутствующие или замаскированные значения;
два резервных слота также пустые. Причина блокировки записи — не
неизвестные пароли, а неполное чтение остальных параметров формы.

## Фактические функции текущего Z11

Из текущей страницы отдельно извлечены `f_get_miner_conf` и
`f_submit_miner_conf`. Только после их разбора установлено текстовое
совпадение обеих функций с ранее прочитанной формой Z15.
Это сравнение реального кода двух страниц, а не вывод по названию модели.

Submit использует POST `/cgi-bin/set_miner_conf.cgi` и 15 полей:

| Источник | Точные поля запроса |
| --- | --- |
| `pools[0].url/user/pass` через DOM | `_ant_pool1url`, `_ant_pool1user`, `_ant_pool1pw` |
| `pools[1].url/user/pass` через DOM | `_ant_pool2url`, `_ant_pool2user`, `_ant_pool2pw` |
| `pools[2].url/user/pass` через DOM | `_ant_pool3url`, `_ant_pool3user`, `_ant_pool3pw` |
| Checkbox beeper / temperature override | `_ant_nobeeper`, `_ant_notempoverctrl` |
| Checkbox / текст ручного вентилятора | `_ant_fan_customize_switch`, `_ant_fan_customize_value` |
| Частота / напряжение | `_ant_freq`, `_ant_voltage` |

Тело — `application/x-www-form-urlencoded; charset=UTF-8`, **не JSON**.
Локальный jQuery 1.10.2 обрабатывает объект `data` с `processData:true`;
`dataType:'json'` описывает ответ. Библиотеки jquery/json2/xhr совпадают
с отдельно прочитанными файлами Z15; прикладных изменений сериализации
в форме и её зависимостях нет.

Из шести непуловых полей известно только текущее значение частоты.
Не прочитаны `bitmain-nobeeper`, `bitmain-notempoverctrl`,
`bitmain-fan-ctrl`, `bitmain-fan-pwm`, `bitmain-voltage`.
Форма вывела бы из отсутствия первых трёх строки `false`,
а для fan PWM и voltage отправила бы пустые строки.
Безусловное чтение отсутствующего voltage перезаписывает начальную
заготовку `undefined`; jQuery сериализует его как пустое значение.
Пять прочитанных `api-*`/`bitmain-use-vil` полей вообще не входят в POST.

Поэтому копирование defaults не гарантирует сохранение настроек.
Частичная отправка только девяти pool-полей тоже не подтверждена:
неизвестно поведение сервера при отсутствии остальных параметров.
Нужны источник пяти фактических значений либо проверенный серверный
контракт сохранения непереданных полей.

Success и error одинаково вызывают reload без проверки тела ответа.
Ack, применение и возможный серверный перезапуск неизвестны.
Явной команды reboot в submit-функции нет; это не доказывает отсутствие
перезапуска майнера внутри setter.
