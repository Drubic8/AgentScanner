## Изменения исходников

- Модель для алгоритма берётся также из VERSION и системной информации.
- Для известных Stock Z9/Z11/Z15 восстановлено прежнее преобразование
  полей GHS/MHS в Sol/s; для Z15 Pro/Z15+ — из kSol/s в Sol/s.
  Это правило совместимости прежнего кода, а не новая аппаратная сертификация.
  Неизвестные модели Equihash требуют явного mapping в профиле.
- Отображаемые единицы фиксированы по алгоритму: X11 — GH/s,
  Equihash — kSol/s. Числовая телеметрия остаётся в базовых единицах.
- Температурные группы `61-67-64`, массивы датчиков и числовые строки RPM
  разбираются без потери значений.
- Для полного ответа STATS с идентификацией Z15 восстанавливаются пропущенные
  разделители и завершающие запятые JSON. Строковые значения не переписываются;
  обрезанные ответы и неподтверждённые модели не исправляются автоматически.
- Сон подтверждается конфигурацией `bitmain-work-mode` / `miner-mode`.
  При отсутствии режима нулевой хешрейт сам по себе означает неизвестное
  состояние, а не подтверждённую неисправность или сон.

## Уточнение каналов вентиляторов Z15

Дополнительное устройство Z15 отдаёт `fan1=4320`, `fan3=30600`, остальные каналы — 0.
Модель и сборка прошивки совпадают с Z15, использующим `fan3/fan4`. Поэтому номера
каналов нельзя фиксировать по модели или версии прошивки. Веб-интерфейс скрывает
все нулевые показания; этот подход также скрывает остановившийся вентилятор.

Сканер запоминает пару каналов после наблюдения двух положительных показаний у
Z11/Z15/Z15e. При следующих опросах того же идентифицированного устройства нулевые
обороты сохраняются, отсутствующее показание обозначается прочерком. Пара хранится
в локальном паспорте и переживает перезапуск. Повторное использование требует
наличия SN или MAC и совпадения отпечатка модели, прошивки, API и идентификаторов.
Появление активного канала вне сохранённой пары заставляет пересмотреть привязку.

Если при первом опросе виден только один работающий вентилятор или все показания
нулевые, сканер выводит доступные каналы с номерами, например `fan1=0 fan2=0 ...`.
Это сохраняет неопределённость: ответ API не позволяет отличить неиспользуемый
разъём от подключённого, но остановившегося вентилятора.

Адресная проверка чтением после исправления (первый и повторный опрос):

| Устройство | Определённые каналы | RPM |
|---|---|---|
| Z15 с альтернативным подключением | fan1 / fan3 | 4560 / 30600 |
| Z15 с ранее проверенным подключением | fan3 / fan4 | 3960 / 3960 |

Значение 30600 передаёт само устройство; сканер его не ограничивает и не пересчитывает.
Причина этого показания отдельно не установлена. Изменение 4320 → 4560 произошло
между опросами. Нули, отсутствующие датчики, смена идентификатора и восстановление
пары после перезапуска проверены на подменённых данных без вмешательства в ASIC.

`python -m unittest discover -s tests -q`: **86 тестов успешно**.

## D9, S21+ и L7: защищённый API во сне

| L7 | Mon Jan 30 09:39:14 CST 2023 | Sleep, хешрейт недоступен | Ранее NO PROFILE; теперь AUTH REQUIRED для сохранённой записи |

Все три конфигурации содержат `bitmain-work-mode=1` (строка или число).
Пароли проверены с разрешёнными пользователем учётными данными, не добавлены в
код и не устанавливаются автоматически. У L7 CGMiner API на 4028 не отвечает;
HTTP позволяет установить модель и сон, но не даёт в этих запросах числового
хешрейта. Отсутствующее значение остаётся прочерком.

Исправлена классификация неуспешной идентификации: если HTTP-запросы получили
ошибку авторизации, ранее сохранённая запись показывает AUTH REQUIRED с
пояснением настройки доступа вместо NO PROFILE. Её состояние остаётся Unknown,
телеметрия отмечена устаревшей; сон не предполагается без чтения конфигурации.
Если признаков отказа авторизации нет, NO PROFILE сохраняет прежний смысл.

В GUI следует отметить нужные Stock-устройства галочками и открыть «Доступ к ASIC»,
затем указать их логин, пароль и Digest. Данные доступа действуют только в текущем
сеансе. При разных паролях Stock и VNish используйте настройки выбранных устройств.

Регрессии покрывают потерю авторизации у HTTP-only спящего ASIC, сохранение
признака устаревших данных и восстановление после возвращения доступа.
Полный прогон: **97 тестов успешно**. Команды управления в этой проверке не выполнялись.

## 01.10.2026: T21 / S21, таймаут режима и правила мощности

В сохранённых результатах GUI от 01.10.2026 у `10.33.11.4`, `.2`, `.5`, `.50`
статус Unknown сопровождался `config:ReadTimeout`; у `.4` и `.5` также
`system:ReadTimeout`. Отдельное чтение режима у T21 `.4` и S21 `.47`
вернуло `bitmain-work-mode="1"`, то есть сон.

Добавлен один повтор GET конфигурации после таймаута для Stock Antminer:
ожидание не меньше 4 секунд, ограниченное оставшимся бюджетом опроса устройства.
Успешные чтения и отказы авторизации этот повтор не вызывают. При уточнении
общего профиля до точной сборки уже выполненные запросы не дублируются.
Если режим так и не прочитан, выводится `CONFIG TIMEOUT`; нулевой хешрейт
по-прежнему не является доказательством сна.

Повторный параллельный опрос всех девяти адресов со скриншота — `.2`, `.3`, `.4`,
`.5`, `.6`, `.47`, `.48`, `.49`, `.50` — вернул **Sleep без ошибок**.
В этом аппаратном прогоне таймаут не повторился; восстановление после задержки
проверено отдельно имитацией ReadTimeout в регрессионных тестах.

Изучены только чтением страницы настроек самих устройств:

| Модель / точная сборка | Скрипт веб-интерфейса | Поле записи / проверка |
|---|---|---|
| T21 / `Thu Sep 26 11:39:05 CST 2024` | `/js/miner.4dc679.js` | HEM: `miner-mode=2`, чтение `bitmain-work-mode="2"` |
| S21 / `FR-1.12(251009-S21)` | `/js/miner.2a6d03.js` | LowPower: `miner-mode=3`, чтение `bitmain-work-mode="3"` |

Для этих сборок добавлены отдельные правила HEM / LowPower и возврата
к обычному режиму (`miner-mode=0`). Сохраняются пулы, настройки вентилятора,
`bitmain-hashrate-percent`, а у S21 — `bitmain-user-ip-cat`.
Отсутствующая частота не подставляется: веб-интерфейс также опускает
`freq-level`, когда `bitmain-freq-level` отсутствует в ответе.

**Команды мощности не отправлялись на оборудование.** В каталоге они имеют
статус `unverified` и доступны только при явном включении экспериментального
управления. Такая смена режима может вывести устройство из сна.
Полная аппаратная приёмка этих режимов не отмечена.
Исходники обновлены, EXE не собирался.

## 01.10.2026: T21 от 16.01.2025 — полный прогон команд

С разрешения пользователя на `10.33.17.27` проверены все применимые команды
профиля `bitmain.stock.t21.20250116`: точная модель `Antminer T21`, системная
сборка `Thu Jan 16 11:00:25 CST 2025`, CGMiner API `3.1`.
Режим LowPower для этой сборки не заявляется: в её меню Normal, Sleep и HEM.

Контракт подтверждён веб-интерфейсом устройства:
`/js/miner.b91570.js`, `/js/index.4be6b1.js`.
Исходное состояние: Normal (`bitmain-work-mode="0"`), `blink=false`.

| Команда | Ответ / независимая проверка |
|---|---|
| Перезагрузка | GET `/cgi-bin/reboot.cgi`, HTTP 200; последующий uptime **250 → 0 с** |

При первом прогоне сон применился, но обработчик счёл `M000` отказом.
Этот код разрешён только в правилах смены режима проверенной сборки T21;

исключений потокового чтения urllib3 в штатные сетевые ошибки requests,
чтобы такой обрыв не завершал сканирование необработанным исключением.
