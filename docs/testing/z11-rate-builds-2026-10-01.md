# Z11: разные единицы хешрейта в сборках 2019 года

01.10.2026 выполнены только запросы чтения к двум указанным пользователем Z11:
CGMiner version/stats/summary, HTTP get_system_info.cgi и minerStatus.cgi.
Команды управления не отправлялись.

| Сборка CompileTime | API / Miner | GHS 5s / GHS av в API | Правильное отображение |
| --- | --- | --- | --- |
| Tue Apr 23 13:15:06 CST 2019 | 3.1 / 9.0.0.5 | 227.40 / 70.6 | 227.40 / 70.60 kSol/s |
| Thu Oct 24 11:09:07 CST 2019 | 3.1 / 9.0.0.5 | 147769.98 / 140476.54 | 147.77 / 140.48 kSol/s |

В апрельском minerStatus.cgi значения GHS 5s и GHS av выводятся напрямую.
Заголовки старой страницы ошибочно названы MH/S. В октябрьской странице заголовок
KSol/S, а JavaScript делит оба поля на 1000. Дополнительное подтверждение масштаба:
сумма chain_rate1..3 в апрельском ответе составляет 227.41, в октябрьском — 147.77.
Сравнивались ответы одной операции чтения каждого устройства; хешрейт меняется.

Исправление: отдельный профиль bitmain.stock.z11.20190423 сопоставляет модель,
API и CompileTime. Его метрики задают kSol/s как исходную единицу. Внутри сканера
хранятся Sol/s, поэтому таблица и суммарный хешрейт получают одинаковый масштаб.
При недоступности SUMMARY используется STATS. Отсутствующее значение не заменяется
нулём; корректный ноль SUMMARY имеет приоритет над STATS.

Автоматические проверки: tests/test_z11_rate_builds.py и обезличенный
tests/fixtures/antminer_z11_rate_builds.json. Проверены обе сборки, отсутствие HTTP,
резервный источник, нули, малые значения, отсутствие показаний и границы профиля.
API/Miner совпадают у обеих сборок, поэтому этих двух полей недостаточно для выбора
масштаба. По величине хешрейта единица не угадывается.

Счётчики chain_hw1..3 апрельского устройства ненулевые. Исправление единиц не
исправляет состояние оборудования и не подтверждает его фактическую производительность
на пуле. Показания платы и предупреждения обрабатываются прежним способом.
