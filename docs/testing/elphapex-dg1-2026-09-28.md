## Исправления программы

- Код успешного ответа M000 разрешён только обработчику Elphapex; ошибки других
  кодов по-прежнему отклоняются.
- Подсветка проверяется чтением boolean-поля `blink`.
- Метод перезагрузки исправлен с POST на GET согласно локальной документации.
  Веб-интерфейс этой прошивки также использует GET для `/cgi-bin/reboot.cgi`.
- Смена режима с потерянным HTTP-ответом не повторяется автоматически. Статус
  `unconfirmed` не равен отказу ASIC и требует последующего чтения.

Автоматическая проверка после изменений: **90 тестов успешно**, в том числе
проверки кода M000, отказов API, чтения подсветки, режимов и метода перезагрузки.
Семейство Elphapex не помечено целиком как аппаратно проверенное: результат
относится только к указанному устройству и версии прошивки.

## Длительность пробуждения и показания API

Пробуждение отправлено около 08:22:53 UTC. В 08:31:53 пул показывал 179 принятых
шар (при предыдущем чтении — 143), но оба поля `hashrate` и `rate_real` всех плат
ещё были нулевыми. В 08:32:31 сканер показал 8,98 GH/s и Running. Это около
9,5 минут от команды до наблюдаемого положительного хешрейта плат, а не гарантированный
срок запуска для всех DG1. Добыча возобновилась раньше обновления показаний плат.

Выявлен отдельный недостаток отображения: в этом переходном состоянии сканер
показывает NO HASH, хотя счётчик принятых шар уже растёт. Для исправления нужно
учитывать динамику принятых шар и состояние запуска; подмена хешрейта плат полем
`rate_5s` без подтверждения его единиц и корректности не выполнялась.
