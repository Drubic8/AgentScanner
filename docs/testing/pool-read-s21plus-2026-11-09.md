# S21+: чтение конфигурации пулов Stock и VNish

Дата: **9 ноября 2026 года**. Пользователь указал два адреса для ограниченного
чтения. В этом документе применяются псевдонимы; адресов, SN/MAC, значений
пулов, workers, паролей и токенов нет.

## Область фактической проверки

| Образец | Подтверждённая идентичность HTTP | Что проверено |
| --- | --- | --- |
| `pool-vnish-001` | Bitmain, модель API `s21plus`, VNish `1.3.3`, профиль `bitmain.vnish` v1 | GET info; текущий локальный OpenAPI; получение токена; GET сохранённых settings; три пула со строковыми url/user/pass; распознавание текущим обработчиком |
| `pool-stock-001` | Bitmain, `Antminer S21+`, Stock `Wed Feb 12 18:01:32 CST 2025`, профиль `bitmain.stock` v2 | GET system info и miner config; три пула со строковыми url/user/pass; HTML и статический JS формы; распознавание текущего read-to-write map |

Версия CGMiner API не запрашивалась: TCP-протоколы в клиенте этой проверки
запрещены. Отсутствующее поле версии API остаётся неизвестным. Хешрейт и
принадлежность к конкретному варианту из аппаратного списка не определялись.

Единственный разрешённый POST — `/api/v1/unlock` для получения токена VNish.
POST settings, set_miner_conf, перезагрузка, режимы, подсветка и иные управляющие
операции заблокированы самим клиентом до обращения к сети. Проверка этого
ограничения выполнена отдельно без сети.

## Проверка подготовки без записи

На прочитанных конфигурациях в памяти выполнены `_patch` и `validate_state`
для изменения только worker первого слота, с общим именем `TEST` и
индивидуальной частью по IP либо номеру с ведущими нулями.

На обоих образцах обе формы прошли проверку готовности. Список изменений
содержал только поле `user`; два нетронутых слота сохранились, исходная
конфигурация в памяти не изменилась. Сформированные значения и тела запросов
на ASIC не отправлялись и в отчёт не включались.

## Границы результата

Чтение и допуск к подготовке подтверждены на указанных версиях. **Изменение
пулов на реальных ASIC не испытывалось**: нет результата команды записи,
чтения после неё, проверки связи с пулом или восстановления хешрейта.
Аппаратная отметка поддержки записи и `verified_commands` не повышаются.

Последняя обезличенная сводка, журнал разрешённых запросов и результат расчёта
сохранены в локальном архиве проверки.
Предыдущие попытки сохранены отдельно. Первые чтения выявили установленный
urllib3 2.1.0 без `HTTPResponse.read1`; это ниже требования проекта `>=2.2`.
Рабочее окружение создано на E; успешный прогон использовал requests 2.34.2
и urllib3 2.8.0, как зафиксировано для этих библиотек в build lock.

Следующее аппаратное испытание записи требует конкретных согласованных
изменений и отдельного разрешения. Текущий результат не даёт такого разрешения.
