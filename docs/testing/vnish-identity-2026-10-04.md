# VNish: ложное изменение идентификации перед подсветкой

## Журнал пользователя

В первой группе из 11 устройств подсветка подтверждена у 10; один запрос
пропущен из-за несовпадения модели и идентификатора строки. Ещё два устройства
получили `skipped` при несовпадении версии прошивки, SN, MAC и идентификатора.
После повторного сканирования подсветка подтверждена API у всех 13:
два запроса записи и 11 устройств уже в целевом состоянии. Запись журнала
не доказывает визуальное состояние физического индикатора.

## Воспроизведение

На трёх Antminer L9 с VNish 1.2.6 / 1.2.7 собраны только ответы чтения:
HTTP `info` / `summary`, CGMiner `version` / `stats` / `summary`.
На тех же ответах перестановка endpoint-блоков в словаре меняла модель
между `l9` и `Antminer L9 (Vnish 1.2.6)` / `1.2.7`. Прошивку устройства
для воспроизведения не меняли. Управляющие запросы не отправляли.

Общая рекурсивная функция `first_field` брала первое найденное поле.
Порядок ответов может различаться при обнаружении, использовании кеша
и недоступности отдельного API. Та же функция могла брать прошивку,
серийный номер и MAC из другого endpoint или вложенных данных плат.
Для этих трёх полей точное происхождение значений в первоначальном сканировании
не сохранено в журнале; оно не установлено задним числом.

## Исправление

Для VNish выбран именованный источник `/api/v1/info`:

- Модель: `model`, затем `miner`.
- Прошивка: `fw_version`.
- SN: верхнеуровневое поле `serial`.
- MAC: `system.network_status.mac`.

Нет данных HTTP — нет подстановки SN платы или метаданных Stock.
При наличии текущей версии прошивки и SN/MAC исчезновение CGMiner API
не меняет fingerprint; совместимость управляющего интерфейса по-прежнему
проверяется перед записью. Настоящее изменение модели, прошивки, SN или MAC
продолжает блокировать команду. Защита от повторной отправки VNish LED сохранена.

Проверки с подменённым транспортом покрывают порядок endpoint-блоков,
исчезновение CGMiner, изменения его отображаемой модели, отсутствие HTTP
идентификации, одну запись LED и запрет записи при реальном изменении устройства.
Аппаратная массовая подсветка после исправления требует проверки пользователем.
Исправление включено в выпуск 2.2.3 для Windows и Android.
