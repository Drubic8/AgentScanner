# WhatsMiner M61: совместимость RPC 3 — 01.10.2026

## Наблюдение на оборудовании

Указанный пользователем M61_VL50 ответил на `get.device.info` через TCP 4433:

- `system.api`: `3.0.5`;
- `system.fwversion`: `20260908.12.Rel2`;
- `system.apiswitch`: строка `1`;
- `system.ledstatus`: `auto`;
- `miner.working`: строка `true`;
- соль авторизации присутствует (значение не сохраняется в отчёте).

На первоначальном этапе выполнены только запросы чтения. Результат последующей
проверки LED приведён ниже. Сон, пробуждение и reboot на реальном устройстве
в этом этапе не испытывались. `hardware_verified_commands` остаётся пустым.

Причина исходного сообщения `unsupported`: диспетчер требовал аппаратную отметку
для точной сборки и не учитывал документированную совместимость RPC 3.

## Изменение

`miner_scanner/whatsminer_compatibility.py` распознаёт успешный структурированный
ответ `get.device.info` с API 3.0.x, моделью и булевым состоянием working
(также допускаются строки true/false). Для разрешения записи нужны apiswitch=1
и непустой salt. Отпечатки веб-страницы для этого протокола не требуются.
Неизвестные версии протокола не получают разрешение по одному названию модели.

Команды:

| Действие GUI | RPC |
| --- | --- |
| Сон | set.miner.service, param=stop |
| Пробуждение | set.miner.service, param=start |
| Подсветка | set.system.led, массив описаний мигания |
| Выключить подсветку | set.system.led, param=auto |
| Перезагрузка | set.system.reboot, без param |

Перед записью на том же соединении получается новая соль, повторно проверяются
совместимость, модель и версия прошивки. Токен: первые восемь символов Base64
SHA256(command + password + salt + timestamp). Пароль не отправляется открытым
полем RPC и не попадает в журнал. После записи проверяются working или ledstatus;
принятый reboot остаётся неподтверждённым до отдельной проверки перезапуска.
Таймаут не вызывает повторную запись. Код -4 даёт объяснение проблемы доступа.

## Настройка доступа в GUI

В «Доступ к ASIC» добавьте профиль семейства WhatsMiner, укажите IP/подсеть,
учётную запись API (`super` либо `user1`–`user3`) и её пароль. Выбранный в редакторе
HTTP Digest/Basic не участвует в авторизации TCP RPC. Сканирование не требует
пароля, запись требует подходящей учётной записи, включённого API Write и права
на конкретную команду. Программа не меняет пароль или разрешения автоматически.

В разделе Permissions [официальной документации](https://apidoc.whatsminer.com/)
указана смена стандартного пароля admin. Но официальный демонстрационный код
`docs/Whatsminer demo/whatsminer.py` использует account=super, password=super,
и эта пара принята проверенным M61. Поэтому требование сменить пароль нельзя
автоматически переносить на эту пару и все прошивки. Стандартный профиль программы
теперь повторяет пару из демо; изменённые пароли задаются отдельными профилями.
Наличие открытого порта не доказывает наличие прав записи.

Документация проверена по текущей индексируемой странице версии 3.0.5 и локальной
копии `docs/whatsminer_official_api.md`. Разделы: Getting Started, Token Generation,
set.miner.service, set.system.led, set.system.reboot.

Тесты `tests/test_whatsminer_commands.py` используют имитацию RPC: авторизация,
эталон токена, сон/пробуждение, LED, reboot, отказ доступа, подмена идентичности,
смена прошивки/переключателя до записи, неподтверждённое состояние и идемпотентность.

## Последующая аппаратная проверка LED и регрессия авторизации

После предоставления официального демо выполнен один `set.system.led` для
включения подсветки на согласованном M61_VL50 (API 3.0.5). Использована пара
super/super из демо. API принял команду, повторный get.device.info вернул
`system.ledstatus=flash`. Первый результат диспетчера был unconfirmed:
он ошибочно ожидал только manual. Обработчик исправлен: flash и manual означают
включённую подсветку; auto — возврат в автоматический режим. flash также сохраняет
доступность команды identify_off при следующем сканировании.

В старом коде до рефакторинга (коммит 9bc89e9, handlers/miner_actions.py)
использовалась учётная запись super и список стандартных паролей, включавший super.
Отсутствие рабочего значения в новом общем профиле было регрессией. Восстановлена
конкретная пара из официального примера, без возврата перебора паролей при записи.

Прежний пустой стандартный профиль мигрирует только при совпадении имени,
семейства, account=super, области * и включённого состояния. defaults_revision=2
позволяет пользователю впоследствии явно очистить пароль без его восстановления.
Произвольные профили и непустые пользовательские пароли не меняются.

Работа WhatsminerTool при выключенном API не исследовалась; демо использует
4433 и авторизацию, оно не доказывает механизм обхода переключателя API.
