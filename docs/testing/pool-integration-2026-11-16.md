# Локальная проверка редактора пулов — 16 ноября 2026

Проверка относится к исходникам локальной Windows-программы. Обращений к ASIC
и аппаратных записей в этом этапе не было. Она не расширяет матрицу моделей
и не подтверждает применение настроек на оборудовании.

## Исправление буквального пароля

Раньше новый пароль `***` или `•••` ошибочно воспринимался как маска ответа API
в ветках Stock, VNish, DG1+ и PitBit C096. Теперь номера слотов с явным вводом
хранятся в приватном подготовленном плане и участвуют в проверке его целостности.
Исключение действует только для выбранного поля `pass`; нетронутые слоты,
URL/worker, непуловые настройки и hotel pool не получают такого разрешения.

Прочитанная маска без явной замены по-прежнему блокирует отправку. Если после
записи API возвращает маскоподобный пароль, даже совпадающий с вводом, результат
остаётся `unconfirmed`. Ответ API об успешном приёме учитывается отдельно;
автоматического повтора команды нет.

## Проверки

- `scripts/check_scanner.py`: **1043 теста**, ошибок нет, **22 пропущены**;
  время unittest — 185,443 с. Лог: локальный архив проверки.
- Новые интеграционные случаи в `tests/test_pool_password_provenance.py` соединяют
  настоящий planner и обработчики с офлайн-транспортами: буквальные пароли,
  совпавшая прочитанная маска, сохранность других полей, подмена provenance,
  изменившаяся конфигурация, неопределённый readback и отсутствие повторов.
- Исходный GUI запущен через `--smoke-test` с отдельными каталогами настроек
  и SQLite на E. `source-smoke/result.json`: `ok=true`, `network_used=false`.
  Проверены открытие редактора из выбранных строк, числовые суффиксы,
  предпросмотр, применение только готовых строк, защита от двойного нажатия,
  разные результаты в группе и освобождение введённых паролей.
- Проверка WhatsMiner шифрования использует известный блок AES-256 и полный
  блок PKCS7; выполняется локально, без RPC и оборудования.

Рабочие результаты GUI находятся в локальном архиве проверки.
Снимки `pool-settings-edit.png`, `pool-settings-preview.png` и
`pool-settings-results.png` просмотрены; пароли скрыты. Применение в этом
сценарии подменено искусственными результатами, а не отправлено на ASIC.

## Проверка упакованной программы

Из текущей рабочей копии собран изолированный проверочный EXE:
локальный архив проверки.
Версия приложения сохранена — `2.6.0`; использованы Python 3.14.5,
PyInstaller 6.21.0 и установленное тестовое окружение. Проверочный spec
сохраняет сбор данных и проверку источников native DLL из основного spec,
меняя только пути вывода, имя файла и описание проверочной сборки.
Это не прогон штатного релизного окружения из `requirements-build.lock`.

Запущен именно полученный EXE с `--smoke-test`, отдельными каталогами настроек
и SQLite на E. `frozen-smoke/result.json`: `ok=true`, `network_used=false`;
все признаки `pool_settings_editor`, `pool_settings_preview`,
`pool_settings_apply_simulated`, `pool_passwords_cleared`,
`whatsminer_aes_pkcs7` равны `true`. Основной smoke также проверил карточку,
журнал, CSV/XLSX/PDF, импорт логов и отмену чтения карточки.

Сведения о среде, SHA256 файла и исходников сохранены в локальном архиве проверки; хеши проверяемых
исходников до и после сборки совпали. Лог — `build-validation.log`, снимки
и итог упакованного запуска — каталог `frozen-smoke/` рядом с ним.
Штатный релиз не заменялся и не публиковался, версия проекта не менялась.

## Следующий этап

Пользовательская инструкция обновлена под фактические кнопки и пять реализованных
веток API. Для одиночного аппаратного пилота и дальнейшей небольшой группы

Z15e, Avalon 1346-110 и Elphapex DG1; другие версии кастомных API проверяются
самостоятельно. Границы — в [матрице совместимости](../development/pool_configuration.md).
