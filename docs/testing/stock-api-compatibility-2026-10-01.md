# Распознавание совместимости Stock API — 01.10.2026

В этом этапе выполнялись только GET и обычный опрос телеметрии. Управляющие
команды на оборудование не отправлялись. Фактические прежние проверки T21/L9
остаются в отдельных журналах и не распространяются автоматически на другие сборки.

| Устройство | Страница настроек | Распознанные режимы |
| --- | --- | --- |
| T21, 16.01.2025 | miner.b91570.js | Normal, Sleep, HEM |
| T21, 26.09.2024 | miner.4dc679.js | Normal, Sleep, HEM |
| S21, FR-1.12(251009-S21) | miner.2a6d03.js | Normal, Sleep, LowPower |
| S21+, компонент platform[AML] | miner.c8af43.js | Normal, Sleep |
| L9, компонент 86.48-2.0.0 | miner.0ef2dc.js | Normal, Sleep |

Все пять устройств также вернули знакомый интерфейс reboot/LED и булевый blink.
Компонентная версия не подменяет дату сборки в журнале аппаратных испытаний.
Модель и доступность опций сопоставлялись с ветвлениями JS, а формат записи — с
`saveMineSet` и загрузкой `get_miner_conf.cgi`. Вариант S21+ пишет
`bitmain-work-mode`, остальные перечисленные — `miner-mode`.

У T21 от 16.01.2025 фактическая конфигурация имеет один заполненный пул без поля
pass и два пустых объекта. Это допустимые ответы: сканер сохраняет их без
добавления паролей или выдуманных значений. Повторное чтение после уточнения
валидатора подтвердило доступность Normal/Sleep/HEM.

В этой сети первичный полный опрос с определением интерфейса занял примерно
0.4–1.3 секунды на устройство. Это наблюдение пяти устройств, не нагрузочный тест
и не гарантия времени в другой сети. Интерфейс кэшируется при обычном мониторинге;
перед командой всегда читается заново.

Автотесты с синтетическим HTTP проверяют другие даты при том же интерфейсе,
разные варианты S21+, разные ключи и типы режима, отсутствие HEM/Low,
LED/reboot, сохранение пулов, изменение интерфейса/схемы перед записью,
ограничение ссылок на локальные assets, дедлайн и отсутствие повторной отправки.

Сырые конфигурации и учётные данные в этот журнал не включены.
