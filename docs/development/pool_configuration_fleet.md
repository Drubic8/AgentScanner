# Пулы и workers: модели парка пользователя

Источник — список пользователя от **9 ноября 2026 года**: **23 модели,
40 вариантов обозначений**. Это аппаратная ось задачи. Пользователь отдельно
уточнил: список **не перечисляет VNish, PitBit и другие кастомные прошивки**.
Установленная прошивка, её версия и интерфейс API для каждой строки неизвестны.
Ни хешрейт в названии, ни слово Antminer не означают установленную Stock.

Список не содержит IP, паролей и идентификаторов устройств. Он не является
ответом API или разрешением на подключение, запись настроек либо перезагрузку.
Одна строка может представлять много ASIC; 40 вариантов не означают 40 устройств.
Модельный fixture: [`pool_fleet_models.json`](../../tests/fixtures/pool_fleet_models.json).

Повторяющиеся названия производителей развёрнуты из групп исходного списка.
Запись скоростей сохранена: `13,6G`, `216th`, кириллические `М`/`Т`, отсутствие
единицы у `Z15e_200` и отсутствие скорости у `M50S++`. Для группировки
WhatsMiner кириллическая `М` приведена к латинской `M` только в отдельном
имени модели; исходные строки `labels` fixture остаются без такой замены.
Это учёт списка, а не правило распознавания прошивки в программе.

## Как читать таблицу

- **S** — для этого имени модели существует карта записи пулов в текущем
  Stock backend. Нужны фактически установленная Stock, совпадающий изученный
  интерфейс/полный конфиг, доступ и сохранение нетронутых полей. Это кандидат,
  а не подтверждённая совместимость указанного варианта или каждой прошивки.
- **S?** — для Stock этой модели карты записи пулов сейчас нет. Это ограничение
  Stock-ветки, а не запрет настройки данной аппаратной модели с другим API.
- **V** — при фактическом наличии VNish отдельно проверяются профиль Bitmain/VNish,
  текущий OpenAPI settings и схема конфигурации. Имя/хешрейт модели не заменяют
  эту проверку. Таблица не утверждает, что VNish существует для каждой модели.
- **P?** — для этого сочетания нет подтверждённого pool-write контракта PitBit.
  Отдельная узкая ветка `S21+_i / incm.C096 / API 3.1` описана ниже;
  поддержка сна/LED других сборок не разрешает их пулы.
- **Другие API?** — требуется самостоятельный подтверждённый контракт установленной
  прошивки, включая авторизацию, слоты, пароли, применение и readback.
- **—** — установка данной кастомной прошивки из аппаратного списка не следует;
  совместимость не заявлена. Для фактически другого API понадобится отдельная
  идентификация и проверка, а не подмена производителя.

В исходном аппаратном списке **фактическая версия прошивки неизвестна**.
На отдельном S21+ Stock `FR-1.15(250422-S21+)` проверена запись только worker
третьего слота с сохранением остальных настроек
([протокол](../testing/pool-write-s21plus-worker-2026-11-16.md)).
Другие модели/контракты и изменение URL/пароля аппаратной отметки не получают.
Варианты с разным хешрейтом не
получают автоматическое разрешение от соседнего варианта той же модели.

## Границы соответствия имён

Отдельно прочитан WhatsMiner `M50_VH75`, Stock `20260908.12.Rel2`, API `3.0.5`:
три runtime-пула получены, паролей в ответе нет. Команды записи не выполнялись.
Хешрейт этого образца не запрашивался; его нельзя автоматически отнести к
обоим указанным вариантам M50. [Протокол](../testing/pool-read-whatsminer-m50-2026-11-09.md).

Для двух предоставленных пользователем S21+ подтверждены чтение конфигурации
и подготовка без записи: VNish `1.3.3` и Stock `Wed Feb 12 18:01:32 CST 2025`.
Хешрейт этих образцов не запрашивался: их нельзя автоматически приписать
конкретному варианту скорости из таблицы. Подробности и границы —
[в протоколе чтения](../testing/pool-read-s21plus-2026-11-09.md).

Отдельно предоставлен `Antminer S21+_i`, PitBit `incm.C096`, API 3.1.
Native Type/Miner отличаются от модели/даты HTTP-оболочки; новая ветка
опирается на native identity и точные хеши React-интерфейса. Она меняет
только три пользовательских пула, сохраняя их индексы, отдельный hotel pool,
fee и остальные поля. Запись блокируется при флаге обновления прошивки.
Хешрейт этого образца не запрашивался: отнесение к 235T не устанавливалось.
[Протокол C096](../testing/pool-read-pitbit-c096-2026-11-09.md).

`S21++` не является псевдонимом `S21+`; `S19k Pro` не является `S19`;
`Z15`, `Z15e` и `Z15 Pro` — отдельные аппаратные обозначения. Сходное имя,
совпавший хешрейт и предположительно одна плата управления не доказывают
одинаковое сохранение настроек. Если для конкретного имени карты Stock нет,
её нельзя заменить картой соседней модели.

Для отдельно предоставленного S19k Pro, Stock `Wed Nov 15 14:47:56 CST 2023`,
прочитаны полная конфигурация и конкретная форма сохранения. Добавлена её
собственная карта пулов с проверкой HTML/JS, без переноса совместимости с S19
или разрешения управления питанием. Вариант 120T из аппаратного списка
не присваивается образцу автоматически: его хешрейт не запрашивался.
[Протокол чтения S19k Pro](../testing/pool-read-s19k-pro-2026-11-09.md).

Добавлен отдельный обработчик для точного интерфейса DG1+ V1.0.4; подготовка
worker по IP/номеру и пароля прошла в памяти, setter не отправлялся.
Хешрейт этого образца не запрашивался; конкретный вариант скорости из
аппаратного списка ему не присвоен.
[Протокол чтения DG1+](../testing/pool-read-elphapex-dg1plus-2026-11-09.md).

В то же время отсутствие Stock-карты не выключает независимо подтверждённый
VNish settings API на подходящем устройстве. Для каждого фактического сочетания
**модель × прошивка × версия × API** проверка выполняется самостоятельно.
Общая цель включает кастомные прошивки; этот аппаратный список её не сужает.

Следующий источник доказательств для заполнения неизвестных ячеек —
обезличенные ответы полной конфигурации и описание реальной формы записи
конкретного интерфейса. Список моделей сохраняется как область проверки;
неподтверждённые ячейки остаются задачами разработки, а не считаются завершёнными
после появления кнопки или синтетического положительного теста.
