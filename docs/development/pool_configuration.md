# Настройка пулов и workers

Дата проверки области совместимости: **16 ноября 2026 года**.

Аппаратный список пользователя — **23 модели / 40 вариантов**, без указания
прошивок — ведётся в [отдельной матрице парка](pool_configuration_fleet.md).
Она сохраняет отдельную проверку Stock, VNish, PitBit и других API на каждой
модели; хешрейт в названии не определяет установленную прошивку.

Функция предназначена для локальной Windows-программы и общего Python-ядра.
Выделение устройства или группы не означает разрешение любой управляющей команды:
перед записью проверяются текущая идентичность, интерфейс, конфигурация и доступ.
В рамках разработки выполняются локальные проверки на подменённых ответах.
16 ноября на S21+ Stock `FR-1.15(250422-S21+)` проверено изменение только worker
третьего слота, с положительным ack, полным совпавшим чтением и сохранением
остальных настроек. Изменение URL/пароля и групповые записи на оборудовании
этим прогоном не подтверждаются. [Протокол](../testing/pool-write-s21plus-worker-2026-11-16.md).

На двух S21+ отдельно выполнены чтение конфигурации и проверка подготовки
без отправки: [Stock от 12.02.2025 и VNish 1.3.3](../testing/pool-read-s21plus-2026-11-09.md).
Это аппаратная проверка чтения и реальных структур; отметка аппаратной
совместимости записи от неё не повышается.

## Имена workers

Часть **до точки одинакова** у выбранных ASIC. После точки находится
индивидуальная часть. При общем имени `TEST`:

| Способ | Пример |
| --- | --- |
| Полный IPv4, точки заменены подчёркиваниями | `TEST.192_0_2_10` |
| Последнее число IPv4 | `TEST.10` |
| Порядковый номер от выбранного начала | `TEST.1`, `TEST.2` |
| Номер с ведущими нулями | `TEST.001`, `TEST.002` |

Соответствие «ASIC → итоговое имя» фиксируется при подготовке плана.
Нумерация следует числовому порядку IPv4, а не лексикографической сортировке
строк и не порядку завершения сетевых запросов. Дубли выбранных адресов
не создают повторной записи. Недоступность устройства не сдвигает номера
остальных. Вариант по последнему числу адреса требует проверки совпадений
между подсетями. Изменение набора устройств или шаблона требует нового просмотра.

Для изменения только индивидуальной части есть режим сохранения текущего
имени до точки. Это имя берётся из свежей конфигурации каждого выбранного слота,
а не из кэша таблицы. Если общие имена устройств различаются или новые workers
совпадают, план не допускается к записи: нужно явно задать единое имя или
выбрать другой способ формирования индивидуальной части.

Это строка имени майнера в пуле, а не MDK Worker как программный процесс.
Наличие точки в принятом пулом логине не отменяет собственных правил пула:
программа проверяет структуру и совпадения имён, но не объявляет успешную
авторизацию в пуле по одному факту сохранения строки.

## Изменяемые поля и результаты

Для каждого слота 1–3 отдельно выбираются URL, worker и пароль. Отсутствие
выбранного изменения означает **сохранить**, а явно заданная пустая строка —
**очистить**, если это допустимо контрактом устройства. Пустое отображение
в основной таблице не является доказательством пустого сохранённого поля.
Для записи читаются настройки через выбранный контракт; проекция `pools.py`
для таблицы не используется как исходник обратной записи. Исключение по
полноте чтения — WhatsMiner RPC3: API показывает runtime URL/worker без
паролей, поэтому пароли всех трёх отправляемых слотов задаются явно.

Предварительный просмотр показывает IP, модель, прошивку и её версию,
слот, текущее и новое значение, доступность операции. Пароли и токены
не включаются в обычный журнал, результаты и экспорт. Для пароля отображается
только факт выбранного изменения. Скрытый или отсутствующий пароль не заменяется
значением `x`, пустой строкой или маской. Если изученный API не позволяет
сохранить неизвестное поле, такая запись не выполняется.

Явно введённый пароль, в том числе строка `***` или `•••`, передаётся буквально.
Номера слотов с явной заменой хранятся только в приватном подготовленном плане
и входят в проверку его целостности. Это разрешение действует лишь для поля
пароля указанных пользовательских слотов; прочитанные маски в нетронутых слотах,
непуловых настройках или hotel pool по-прежнему блокируют запись.
При обратном чтении строка из звёздочек/точек остаётся неоднозначной даже при
совпадении с вводом: сохранение такого пароля получает `unconfirmed`.

Перед применением требуется свежее чтение и сверка с подготовленным планом.
Внешнее изменение настроек или замена устройства означает необходимость
обновить план. Приложение сериализует свои записи одному ASIC; это не создаёт
атомарную транзакцию с другим клиентом или веб-интерфейсом производителя.
Нет автоматического повторения записи, отката настроек или перезагрузки.

Положительный ответ API отдельно от подтверждения сохранения. Таймаут,
неоднозначный ответ и несовпавшее чтение остаются неподтверждённым исходом.
Если API сообщает о необходимости перезапуска, это показывается отдельно:
сохранённая конфигурация не равна уже применённой конфигурации майнинга.
Подтверждение URL/worker не является подтверждением скрытого пароля,
соединения с пулом или поступления shares.

## Различия API, которые нельзя скрывать общей кнопкой

### Antminer Stock

Чтение: `GET /cgi-bin/get_miner_conf.cgi`. Запись:
`POST /cgi-bin/set_miner_conf.cgi`. Имена ключей чтения и записи могут
различаться; существующие изученные соответствия находятся в
[`stock_interfaces.json`](../../miner_scanner/profiles/stock_interfaces.json).
Факт работы `get_miner_conf` недостаточен для произвольного POST полного ответа.
Нужно сохранить режим, частоты, вентиляторы и остальные поля по конкретному
контракту. Для неизвестной конфигурации запись не выполняется.

Дополнительно известны варианты интерфейсов S21/S21+/S21 Pro/S21 XP,
T21, L7/L9, D9, Z15 Pro, KS5/KS5 Pro. Это перечень исследованных интерфейсов,
а не доказательство каждой операции на всех устройствах. У KS5 есть изученный
веб-интерфейс без разрешённых режимов питания; этот факт нельзя превращать
в допуск настройки пулов без самостоятельного доказательства.

Обезличенные read fixtures содержат также Z15
(`Fri Jul 3 11:39:06 CST 2020`), D9 (`Tue May 28 09:27:48 CST 2024`),
Z15 Pro (`Wed Dec 13 11:33:17 CST 2023`), T21
(`Sun Jan 26 18:50:43 CST 2025`), S21
(`Fri Oct 11 16:34:48 CST 2024`) и S21+
(`Tue Apr 22 15:05:57 CST 2025`). Старые A3
(`Fri Dec 29 17:12:57 CST 2017`) и Z11 второй сборки
(`Thu Oct 24 11:09:07 CST 2019`) также относятся к общему профилю.
Read fixture, в котором нет полной конфигурации или формы сохранения,
не расширяет область допустимой записи.

Для записи пулов используются 13 определений веб-интерфейсов и 27 сочетаний
«определение → модель». Для S19, Z11, A3 и D7 карты записи пулов в нём нет:
Stock-ветка изменения пулов этих моделей сейчас возвращает «не поддерживается».
Обнаружение модели, общий профиль Stock, успешное чтение конфигурации или
испытание другой команды не обходят это ограничение. Z15 без суффикса Pro
также не наследует контракт Z15 Pro. Эти ограничения Stock не отменяют
независимую проверку действительно установленного VNish или другого API.

На отдельно предоставленном Z15, Stock `Fri Jul 3 11:39:06 CST 2020`,
прочитаны JSON конфигурации и фактическая старая форма
`/cgi-bin/minerConfiguration.cgi`. Это form-urlencoded POST с 15 полями,
включая девять pool-строк и шесть параметров оборудования. Конфигурация
раскрывает только один из шести — частоту; пять полей вентилятора, напряжения,
звука и температурной защиты отсутствуют. Статические defaults и `undefined`
в UI не подтверждают текущие значения. Запись Z15 пока не включена:
сохранение опущенных полей при pool-only POST не доказано, а копирование
полного запроса формы подставило бы неизвестные параметры.
[Протокол чтения Z15](../testing/pool-read-z15-2026-11-09.md).

На выбранном Z11, Stock `Mon Aug 26 13:37:07 CST 2019`, отдельно прочитаны
JSON конфигурации и `/cgi-bin/minerConfiguration.cgi`. Состав семи полей,
состояния pool-полей и функции отправки проверены на этом образце.
Фактическая форма также отправляет 15 form-urlencoded полей, а пять
nonpool-значений отсутствуют в конфигурации. Это наблюдение текущего Z11,
а не перенос по названию Z15 или другой дате Z11. Запись пока не включена
из-за неподтверждённого сохранения неизвестных параметров.
[Протокол чтения Z11](../testing/pool-read-z11-2026-11-09.md).

S19k Pro имеет отдельный точный интерфейс Stock от 15.11.2023:
`miner.8380a5.js` вместе с известным HTML. Его карта разрешает только
настройку пулов; список новых разрешений управления питанием пуст.
В этой форме текущее значение режима пересылается с исходным строковым
типом, а уровень частоты — под ключом `freq-level`. Опция
`preserve_mode_type` ограничена этим контрактом. Параметры API, частоты,
напряжения и прочие поля, которых нет в форме сохранения, в POST не добавляются.
[Чтение S19k Pro и подготовка без записи](../testing/pool-read-s19k-pro-2026-11-09.md).

`bitmain-user-ip-cat` может дописывать IP прошивкой. При включённой функции
сохранение строки `TEST.001` ещё не доказывает именно это имя в пуле.
Такой флаг нельзя незаметно отключать ради совпадения предпросмотра.

Источники: [совместимость Stock](stock_api_compatibility.md),
[проверка разных интерфейсов](../testing/stock-api-compatibility-2026-10-01.md),
[официальное описание CGI](https://docs.bitmain.com/en/antminer/CONTENTS.html#set_miner_conf).

### VNish

Локальная [`vnish_openapi.json`](../vnish_openapi.json) описывает
`GET/POST /api/v1/settings`, `InputConfig.miner.pools` со строковыми
`url/user/pass` и `SaveConfigResult.restart_required/reboot_required`.
Проверяется соответствующая операция из текущего локального описания устройства;
ссылки на внешние `servers` или `$ref` не являются новыми адресами запросов.
Статистика активного пула и сервисные DevFee/Refund pools не используются
вместо списка пользовательской конфигурации.

Старые проверки L9 1.2.6/1.2.7 и S21+ 1.3.3 относятся к идентификации и другим
командам, а не к записи settings. Авторизация чтения и записи проверяется отдельно.

### PitBit C096

Для отдельно предоставленного `Antminer S21+_i`, `incm.C096`, API 3.1,
прочитаны native `version`, HTTP-конфигурация и React-форма. Версия движка
подтверждается полем `VERSION[0].Miner`, модель — `Type`; дата HTTP-оболочки
2020 года не используется как версия C096.

Обычная форма отправляет JSON `{...currentConfig, pools: editedPools}`
в `/cgi-bin/set_miner_conf.cgi`. Обработчик сохраняет все 23 поля,
индексы обычных пулов `0,1,2`, отдельный `poolshotelfee` и `hotelfeepercent`.
В канонические три редактируемые позиции попадают только пользовательские
URL/user/pass. Режим, вентиляторы, температурные/вольтовые параметры и fee
не пересчитываются. Скрытые пароли любого пересылаемого пула блокируют запись.
`need_update_fw_now` должен быть строго `false`: код не меняет этот флаг
и не запускает обновление прошивки.

Перед записью повторяются native/HTTP identity, конфигурация и проверки двух
точных статических хешей. HTTP-успех вместе с `stats == "success"` считается
ack; `M028` с ошибкой обновления — отказ, без повторения запроса.
Сохранение подтверждается отдельным чтением полного объекта. Перезапуск
и apply не отправляются. Старый C074 и Stock этим допуском не расширяются.
[Контракт C096](pitbit_pool_contract.md),
[протокол чтения и подготовки](../testing/pool-read-pitbit-c096-2026-11-09.md).

### WhatsMiner

На M50_VH75, Stock `20260908.12.Rel2`, API `3.0.5` подтверждено чтение
трёх runtime-пулов; пароля нет во всех трёх. API Write уже был включён,
но команды записи не выполнялись. [Протокол проверки](../testing/pool-read-whatsminer-m50-2026-11-09.md).

Официальная [`set.miner.pools`](https://ces.whatsminer.com/#api-Miner-set_miner_pools)
для RPC3 принимает зашифрованный `param` со списком `pool/worker/passwd`.
Одного токена уже работающих LED/service-команд недостаточно. Состояние
runtime pools не обязательно является независимым чтением сохранённых настроек,
а отсутствие пароля в нём не разрешает очистить пароль при замене worker.

Схема AES-256-ECB/PKCS7 подтверждена официальным Python demo, который совпадает
с оригинальным архивом производителя, и закреплённым
[vendor Worker](https://github.com/whatsminer/whatsminer-mdk-worker/blob/a47fa82020454f9bfa9963ccaaa319b7948e8aa2/lib/protocols/wm-api-v3.js#L126)
производителя. При этом опубликованный encrypted vector использует нулевое
дополнение, а demo дважды сериализует JSON в методе pools. Это конкретные
несогласованности примеров; они не означают отсутствия документированной
команды или неизвестности AES. Выбор совместимого wire-профиля нельзя делать
перебором двух записей на устройстве. Источники, SHA256 и границы — в
[отдельном контракте WhatsMiner](whatsminer_pool_contract.md).

В программе реализован один вариант запроса по reference-клиенту:
AES-256-ECB/PKCS7 и однократная сериализация массива `pool/worker/passwd`.
Он проверяется локально с расшифровкой отправленного параметра. Предпросмотр
требует явные пароли всех трёх слотов; пароль доступа к учётной записи API
не используется как пароль пула. Введённые строки передаются без удаления
пробелов и без подстановки `x`; явное очищение передаёт пустую строку.

Перед единственным setter повторно проверяются идентичность, версия API,
API Write, упорядоченные ID `1,2,3` и неизменность URL/worker. Salt и статистика
не входят в сравнение конфигурации. При непустом `btrom-worker-suffix` запись
блокируется даже для изменения только URL или пароля: runtime account нельзя
без доказательства использовать как имя до автоматического суффикса.
Прочитанные после записи URL/worker обновляют таблицу, но результат остаётся
«не подтверждено», поскольку API не возвращает пароль и сохранённую
конфигурацию. При таймауте setter не повторяется. Аппаратная проверка записи
остаётся отдельным невыполненным этапом.

Legacy API v2 — отдельный протокол на 4028, не ещё одна дата RPC3.
Обнаруженный путь `update_pools` может заполнять незаданные backups пустыми,
пропускать password-only update и вызывать reboot. Эти побочные эффекты нельзя
переносить в общий редактор. Управление API Write/паролями/правами доступа
автоматически не выполняется; исследовательский TCP8889 клиент не становится
зависимостью редактора пулов.

Уточнение по первичному источнику:
[официальное руководство V2.0.5 от 08.05.2023, §3.1 и §4.2](https://aws-microbt-com-bucket.s3.us-west-2.amazonaws.com/WhatsminerAPI2.0.5_20230508.pdf)
описывает запись `update_pools` с тройками `pool1/worker1/passwd1` … `3`
и немедленное переключение. Дополнительный reboot в MDK — поведение клиента,
а не обязательный этап этого документированного запроса. Пример `pools`
содержит runtime URL/User и статистику, но не пароль; у первого показанного
объекта `POOL=1`, `Priority=0`. Нумерацию слотов нельзя автоматически брать
из общего zero-based CGMiner-парсера без проверки конкретного ответа.

### Avalon, Elphapex, Jasminer, iPollo, Goldshell и Generic

На отдельно предоставленном Avalon 1346-110, Stock
`24041001_08b0955_0196aba`, API 3.7, MM317, 09.11.2026 прочитаны `version`
и `pools`: три runtime-записи без пароля. Публичный веб-интерфейс объявляет
форму `POST /login.cgi`; две ограниченные попытки входа существующим профилем
завершились закрытием соединения без HTTP-ответа. Форма настройки пулов
и её сохранение остались недоступны. Это ограничение полученных доказательств
и текущей программной ветки, а не утверждение об отсутствии возможности
менять пулы у самого оборудования.
[Протокол чтения Avalon](../testing/pool-read-avalon-1346-2026-11-09.md).

[Официальное руководство Avalon A10, §2.5](https://github.com/Canaan-Creative/avalon10-docs/blob/master/Universal%20API/Avalon%20A10%20API%20manual-EN.md)
описывает `ascset|0,setpool` с web credentials и одним набором pool/worker/password,
применение после reboot. Это не доказывает сохранение трёх слотов на 1346/MM317.
Ответ примера повторяет пароль worker: сырые ответы нельзя писать в журнал.
API A10 последовательно обслуживает запросы, совместимость LED не равна pools.

Для выбранного Elphapex DG1+ V1.0.4 прочитана актуальная веб-форма:
она получает полный объект `GET /cgi-bin/get_miner_conf.cgi` и пересылает его
в `POST /cgi-bin/set_miner_conf.cgi` с JSON, меняя выбранные pool-поля.
Это самостоятельный проверенный native-контракт, а не предположение по имени
`luci/set_miner_conf2.cgi` из официального массового инструмента.
Новый обработчик сохраняет семь nonpool-полей и их типы, требует три полных
слота и проверяет текущую идентичность, HTML и три JS-хеша. Неизвестные поля,
маски и смена интерфейса блокируют запись. Модель DG1 и другие версии
не получают допуск по одному сходству названия.

Форма не проверяет тело ack: HTTP 2xx само по себе не отмечается как принятие
API. Успех настройки возможен только после свежего совпавшего чтения полного
объекта, включая пароль и nonpool-поля; таймаут не вызывает повтор setter.
Перезапуск или отдельный apply не отправляются. Авторизация protected web
выполняется через профиль Elphapex; стандартный профиль — root/root, HTTP Basic.
[Разбор источников и границ](elphapex_pool_contract.md),
[чтение DG1+ и подготовка без записи](../testing/pool-read-elphapex-dg1plus-2026-11-09.md).

Для Jasminer
`POST minerStatus.cgi` и LED CGI не определяют форму записи пулов. Для iPollo
общий JSON CGMiner не доказывает доступный и постоянный `save`.

На Goldshell HS5 2.2.1 выполнялось
[только чтение MCB](../testing/goldshell-hs5-2026-10-13.md).
[Официальный HS1 CLI](https://github.com/goldshellminer/goldshellminer-cli)
относится к другому классу устройств и не подтверждает запись HS5 через `/mcb`.
Generic HTML `ant_conf` также не задаёт формат CGI/CSRF/auth сохранения.
До появления конкретного контракта эти устройства получают понятный результат
«не поддерживается»; запись по похожему названию команды не отправляется.

### Дополнительная проверка недостающих семейств

Сохранённый `docs/wireshark/antminer pitbit.log` проверен 09.11.2026 только
офлайн через извлечение структуры без значений: 7 140 байт, SHA256

## Проверка и следующий аппаратный этап

В окне настройки есть явное сохранение **сведений о совместимости** в JSON.
Экспорт работает только с результатами текущего предпросмотра и не отправляет
новых запросов к ASIC. В нём остаются обезличенная модель/прошивка/версия API,
имена изученных полей и их типы, наличие/пустота/маска полей слотов, статус
проверки и итог выполнения. IP, MAC, SN, идентификаторы устройств, адреса пулов,
workers, пароли, токены и тела запросов не сохраняются. Неизвестные динамические
имена полей заменены количеством неизвестных полей: сам ключ тоже может быть
секретом. При повторной сериализации применяется тот же белый список.

Сводка поддерживает изучение схем чтения, но не заменяет доказательства формы
записи и её побочных эффектов. Отказ до получения конфигурации содержит только
идентификационные технические данные и статус; отсутствие схемы обозначает
неполученные данные, а не пустую конфигурацию.

Отдельная кнопка **Прочитать сведения о совместимости** выполняет только
известные запросы чтения, без выбора изменяемых полей. Для Bitmain/PitBit и
Elphapex используются их известные CGI-getters; для WhatsMiner сначала
перепроверяется фактический RPC3, затем читается `get.miner.status:pools`.
CGMiner, Jasminer и Goldshell имеют отдельные фиксированные ветки чтения.
VNish проверяет объявленное GET-чтение settings независимо от пригодности
POST-схемы. Авторизация VNish получает токен; настройки майнинга не записываются.
Неизвестная прошивка не наследует URL соседнего семейства.

Такой результат имеет статус `observed`, не содержит `_prepared` и не является
планом исполнения. В отчёте `reading_kind` различает `saved_configuration`,
`runtime` и `unknown`; runtime-список не повышается до сохранённой конфигурации.
`position` — позиция в полученном массиве, а не угаданный номер слота конкретного
RPC. `schema_digest` зависит от типов и структуры, но не от значений настроек.

Реализация отделена от существующего API простых команд:

- `miner_scanner/pool_configuration.py`: `PoolEdit` с `None` для сохранения поля
  и явной пустой строкой для очистки; `WorkerNaming` для общего имени и
  индивидуальной части; `prepare_pool_batch` и `execute_pool_batch`.
- `miner_scanner/pool_backends.py`: распознавание текущего контракта,
  проверка готовности записи без I/O через `validate_state`, построение
  запроса и чтение конфигурации. Новый контракт не определяется именем модели.
- `miner_scanner/pool_evidence.py`: обезличенные структуры без значений
  конфигурации, включая отказ распознавания схемы, и повторная проверка экспорта.
- `miner_scanner/pool_evidence_readers.py`: отдельные разрешённые запросы чтения
  для сбора сведений, не связанные с отправкой управляющей команды.
- `desktop_ui/pool_dialog.py`: отдельное окно с явным применением плана,
  предпросмотром, отменой и результатом каждого ASIC. Открывается из общего
  меню управления выбранными устройствами.

План хранит полную конфигурацию только в приватных полях памяти. Его нельзя
сериализовать в настройки, журнал или отчёт. После выполнения или закрытия окна
планы и введённые пароли освобождаются. Отмена подготовки также освобождает
полученные планы. Один `command_id` записывается до
обращения к setter и не создаёт повторной отправки при повторном исполнении.
Перед записью сверяются и паспорт устройства, и конфигурация из предпросмотра.
Проверенное чтение обновляет только безопасные столбцы пулов в таблице.

Тесты ядра/контрактов/интеграции выполняются без сети:

```shell
python -m unittest tests.test_pool_configuration tests.test_pool_backends tests.test_pool_integration tests.test_pool_profile_coverage tests.test_pool_fleet_inventory tests.test_pool_evidence tests.test_pool_evidence_readers
```

Для интерфейса дополнительно проверяются `tests.test_pool_dialog` и
`tests.test_pool_gui_integration`. Общая обязательная проверка —
`python scripts/check_scanner.py`. Для GUI применяется smoke-команда из
`CONTRIBUTING.md`, с временным каталогом и результатами в отдельном временном каталоге.

Для каждого разрешённого контракта нужны fixtures с сохранением slot order,
пустыми и отсутствующими полями, маской пароля, неизвестными ключами,
отрицательным ack, таймаутом после отправки и несовпавшим свежим чтением.
Обязательны случаи password-only, сохранения двух нетронутых слотов,
индивидуальных workers в группе, отмены и ошибки только части устройств.
Синтетические ответы отмечаются как synthetic.

Только после этого выполняется отдельная согласованная проверка конкретных
IP и действий: чтение до изменения, показ плана, одна запись, чтение сохранённых
настроек, наблюдение фактического имени и связи с пулом, восстановление прежних
параметров при заранее известных паролях. Отсутствие такого испытания сохраняется
в статусе совместимости; успешный локальный тест не является проверкой ASIC.
Порядок и поля для подготовки пилота описаны в
[плане аппаратной приёмки](../testing/pool_write_acceptance.md).
