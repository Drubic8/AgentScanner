# Windows: интерфейс, сборка и обновление

## Запуск

Готовый файл после сборки: `dist/ASIC_Monitor.exe`. Python на компьютере пользователя не нужен. Сборка рассчитана на Windows x64; запуск и отчёты проверяются на текущей Windows 11. Для сканирования компьютер должен иметь доступ к сети ASIC.

При разработке запускайте `gemini_gui.py` из окружения с desktop-зависимостями. В этой рабочей папке подготовлено отдельное `.venv-build`:

```powershell
.venv-build\Scripts\python gemini_gui.py
```

## Новый интерфейс

- Светлая, тёмная и системная темы; выбор сохраняется. Системная тема определяется при запуске и применении настроек.
- Сводка устройств, моделей и хешрейта. Устаревшие значения не включаются в сумму текущего хешрейта; разные единицы выводятся отдельно.
- Поиск по IP, модели, прошивке, пулу и воркеру (`Ctrl+F`). Фильтр состояния и устаревших данных.
- Массовое выделение только видимых строк. При скрытии выбранной строки фильтром её выделение снимается.
- Настройки (`Ctrl+,`): общие, сканирование, столбцы таблицы, PDF, Excel/CSV. Изменения применяются после сохранения; «Отмена» их отклоняет.
- Настраиваемые ожидание ответа и параллельность, обычная/компактная таблица. IP остаётся видимым для управления устройствами.
- Проверка диапазонов до сохранения; сообщения о ходе, остановке и ошибке сканирования. Закрытие окна ожидает завершения текущих операций.
- Экспорт включает **все результаты сканирования**, независимо от фильтра таблицы. Сортировка выполняется до отбора экспортируемых столбцов. PDF использует установленный Windows-шрифт Segoe UI для кириллицы, ширина таблицы подгоняется под страницу.

Основное окно остаётся в `gemini_gui.py`. Оформление, настройки, предпочтения, подготовка отчётов и проверка обновлений выделены в `desktop_ui/`. Этот пакет не используется ядром сканера.

## Сети для сканирования

- Кнопка **Добавить сеть** открывает редактор: название, адреса и предварительный подсчёт IP. Укажите один IP, CIDR (`192.168.1.0/24`), короткий интервал (`192.168.1.1-254`) или полный (`192.168.1.1-192.168.2.10`). Строки, запятые и точка с запятой разделяют диапазоны.
- Ошибки показываются рядом с формой с номером строки; неверный диапазон сохранить нельзя. Пересекающиеся адреса опрашиваются один раз. Лимит одного задания — 4096 уникальных IP.
- **Галочки** выбирают сети для сканирования и сохраняются между запусками. Выделенная строка используется только для изменения и удаления. Если снять все галочки, сканирование не запустится.
- Поиск скрывает неподходящие строки, сохраняя галочки. Переключатель **Все сети** действует на весь список, включая скрытые строки.
- Старые форматы `ip_ranges.json` читаются автоматически; существующие сети без поля `enabled` включены по умолчанию. Замена EXE не удаляет пользовательские сети.
- Удаление запрашивает подтверждение. Если запись файла не удалась, список и галочки возвращаются к прежнему состоянию.

## Настройки и обновления

Настройки и диапазоны записываются в `%LOCALAPPDATA%\ASICMonitor\app_settings.json` и `ip_ranges.json`. Если новых файлов ещё нет, программа читает старые файлы рядом с `gemini_gui.py` или EXE. После первого сохранения используется новая папка. Исходные файлы не удаляются. Папка может быть переопределена переменной `ASIC_MONITOR_DATA_DIR`; расположение SQLite ядра настраивается отдельно через `MINER_SCANNER_DATA_DIR`.

Профили доступа и пароли сохраняются с защитой Windows DPAPI для текущего пользователя;
токены действуют только в памяти сеанса. Настроить доступ можно в настройках **Доступ к ASIC**:
без выделенных строк — для сканирования, с выделением — для выбранных устройств.

Используются существующие `version.json` и `CURRENT_VERSION` в `gemini_gui.py`, а также версия пакета в `pyproject.toml`. Сборщик откажется работать, если они различаются. Windows FileVersion/ProductVersion формируются автоматически из этих значений.

Проверка обновлений выполняется в фоне. Автоматическую проверку можно включить в общих настройках; по умолчанию она отключена. Ручная проверка доступна через **Справка → Проверить обновления**. Версии сравниваются численно, включая случаи `2.10.0` и `2.9.0`.

Начиная с 2.2.2 Windows EXE скачивает обновление из программы. Источник версии — опубликованный GitHub Release; `version.json` используется для локализованного описания только при совпадении версии. Ссылки закреплены за тегом, проверяются размер, SHA256 из `SHA256SUMS.txt` и версия ресурса PE. Разрешены HTTPS GitHub и его серверы выдачи release-assets.

После подтверждения и завершения сканирования и команд приложение сохраняет настройки и запускает отдельный помощник — копию текущего EXE. Он ждёт закрытия обоих процессов PyInstaller, повторно сверяет файлы, сохраняет прежний EXE рядом как `.previous-<идентификатор>.bak` и заменяет файл. Новая программа подтверждает запуск после создания окна. При выходе до подтверждения или ожидании свыше 60 секунд помощник останавливает новый процесс и восстанавливает прежний EXE.

Помощник не использует BAT и не повышает права: папка EXE должна быть доступна пользователю для записи. Сети, настройки и профили доступа остаются в пользовательской папке. SHA256 не заменяет независимую подпись издателя; EXE пока не подписан сертификатом. Если файловая система или антивирус блокирует восстановление, потребуется ручная помощь: резервная копия хранится рядом с EXE. Старые `.previous-*.bak` можно удалить после проверки новой версии. Результат установки — `updates/update-*/status.json` в пользовательской папке.

Переход с 2.2.1 требует однократного ручного скачивания 2.2.2. Из исходников автоматическая замена недоступна: обновляйте Git-копию. Android APK устанавливается вручную.

Компоненты: `update_package.py` — получение и проверка пакета; `updates.py` — Qt-потоки; `update_installer.py` — помощник и восстановление; `gemini_gui.py` — подтверждения, ожидание операций и сохранение настроек.

## Воспроизводимая сборка

На Windows x64 с Python 3.13:

```powershell
python -m venv .venv-build
.venv-build\Scripts\python -m pip install -r requirements-build.lock
.venv-build\Scripts\python scripts/build_windows.py
```

`requirements-build.lock` фиксирует версии зависимостей проверенного окружения. Это фиксация зависимостей, не обещание побайтово идентичного EXE на разных системах.

Скрипт:

1. Проверяет совпадение версий GUI, пакета и манифеста.
2. Запускает проверки ядра и GUI.
3. Собирает один EXE через `ASIC_Monitor.spec` с иконкой, номером версии, Qt, ресурсами профилей и библиотеками экспорта.
4. Запускает **собранный EXE** в режиме `--smoke-test`: без оборудования и внешних запросов, с демонстрационными адресами `192.0.2.x`.
5. Проверяет скриншот из буфера обмена, создание CSV/XLSX/PDF и записывает `dist/SHA256SUMS.txt`.
6. Запускает собранный помощник на временных копиях EXE: замена, путь с кириллицей и пробелами, резервная копия и подтверждение запуска. Результат — `artifacts/exe-update/result.json`.

Перед повторной сборкой закройте запущенный EXE. Удалять всю `dist` не нужно:
сборщик заменяет `ASIC_Monitor.exe` и обновляет его контрольную сумму после проверки.
Старые `.whl` и другие посторонние файлы из этой папки в Windows-релиз не включаются.

В сборку не включаются локальные диапазоны, настройки, пароли, SQLite и служебные файлы других приложений. Иконка — `app.ico`, созданная из общего [векторного оригинала](../../assets/branding/README.md). Сборка не подписана сертификатом издателя.

Снимки окон и результат проверки находятся в `artifacts/exe-smoke/`. Режим проверки также доступен из исходников:

```powershell
.venv-build\Scripts\python gemini_gui.py --smoke-test artifacts/ui-preview
```

## GitHub Releases

Репозиторий уже указан в манифесте: `Drubic8/AgentScanner`. Имя файла **ASIC_Monitor.exe** сохранено, чтобы существующая ссылка `releases/latest/download/ASIC_Monitor.exe` продолжала работать.

1. Загрузить изменения исходников, включая `desktop_ui`, `ASIC_Monitor.spec`, скрипт сборки, lock-файл, `version.json` и иконку.
2. Подготовить номер версии Windows и Android и `docs/releases/<версия>.md`; внести изменения через PR после проверок CI.
3. Создать тег `v<версия>` на коммите с этой версией. Опубликованные теги не перемещать без отдельного согласования владельца.
4. Workflow **Publish Windows and Android release** собирает обе платформы и публикует EXE, тестовый APK и объединённый `SHA256SUMS.txt`.
5. Проверить версии опубликованных файлов и их контрольные суммы. `dist` не коммитится в Git.

Альтернатива локальной сборке: workflow **Windows EXE** в GitHub Actions. Он доступен для ручного запуска или вызывается workflow выпуска, проверяет соответствие тега версии и создаёт артефакт `ASIC-Monitor-Windows`. Сам по себе он не публикует релиз.

## Границы проверки

Автоматические проверки используют искусственные данные, временные файлы и эмуляторы. Они не подтверждают совместимость со всеми прошивками ASIC. Аппаратные проверки и ограничения описаны в матрице совместимости и документации Android; цифровая подпись дистрибутива остаётся отдельной задачей.
