# Чтение логов устройства

`miner_scanner.device_logs` — отдельный адаптер чтения по запросу пользователя.
Он не включается в обычное сканирование и не изменяет режим работы ASIC.

## Поддерживаемые интерфейсы

| Семейство профиля | Вид | Запрос |
| --- | --- | --- |
| `bitmain.stock` и его уточнённые профили | Майнер | `GET /cgi-bin/log.cgi` |
| То же, если первый маршрут отвечает 404/405/501 | Майнер, legacy | `GET /cgi-bin/get_kernel_log.cgi` |
| То же | Система / ядро | `GET /cgi-bin/get_kernel_log.cgi` |
| `bitmain.vnish` | Майнер | `GET /api/v1/logs/miner` |
| `bitmain.vnish` | Система | `GET /api/v1/logs/system` |
| `microbt.rpc3` | Майнер | TCP 4433: `get.log.download`, текущий `miner-state.log` из архива |
| `microbt.rpc3` | Система | TCP 4433: `get.log.download`, текущий `system.log` из архива |
| `elphapex.luci` | Майнер | `GET /cgi-bin/hlog.cgi`; при 404/405/501 — `GET /cgi-bin/luci/hlog.cgi` |

Основания для маршрутов:

- Legacy Stock: официальный исходник Bitmain
  [kernelLog.html](https://github.com/bitmaintech/Antminer_firmware/blob/master/sources/meta-antminer/recipes-bitmianer/lighttpd/lighttpd-1.0/www/kernelLog.html)
  запрашивает `get_kernel_log.cgi` методом GET и читает текст; сам
  [CGI](https://github.com/bitmaintech/Antminer_firmware/blob/master/sources/meta-antminer/recipes-bitmianer/lighttpd/lighttpd-1.0/www/cgi-bin/get_kernel_log.cgi)
  выполняет `dmesg`.
- Modern Stock: `/cgi-bin/log.cgi` документирован в исходном проекте интеграции
  [antminer-log-collector](https://github.com/loo-ven/antminer-log-collector).
  Это независимый источник, а не гарантия Bitmain для всех прошивок. В этой
  реализации маршрут проверен подменами HTTP; аппаратная проверка конкретных
  моделей ещё требуется.
- VNish: поставляемая с проектом [OpenAPI-схема](../vnish_openapi.json),
  `GET /logs/{log_type}`, `LogType` и базовый путь `/api/v1`. Для чтения этой
  схемой не требуется авторизация. Если реальная прошивка отвечает 401/403,
  используются выбранные профили VNish и документированный `POST /unlock`
  с полем `pw`, затем Bearer-токен только для чтения выбранного лога.
- WhatsMiner: официальный [Log API](https://apidoc.whatsminer.com/#api-Log-get_log_download).
  Запрос `{"cmd":"get.log.download"}` и начальный JSON-ответ имеют четырёхбайтовый
  префикс длины little-endian. После успешного ответа с `msg.logsize` по тому же
  TCP-соединению читается указанное число байтов сырого TGZ; дополнительные
  JSON-рамки вокруг фрагментов архива не ожидаются. Границы чтения сокета могут
  отличаться от размера отправляемых устройством фрагментов.
  На M61S+ с API 3.0.5 получение архива проверено без передачи пароля и изменения
  настроек доступа; [аппаратная проверка](../testing/whatsminer-logs-2026-10-31.md)
  не означает подтверждения всех моделей и версий прошивки.
- Elphapex: веб-страницы Log на DG1 / `DG1_SW_V1.0.4` и DG1+ /
  `DG1+_SW_V1.0.4` запрашивают текущий журнал через `GET /cgi-bin/hlog.cgi`.
  Оба маршрута из таблицы проверены на устройствах, отдельно проверен рабочий
  адаптер и диагностический экспорт. [Протокол проверки](../testing/elphapex-logs-2026-10-31.md).
  Поддерживается только `miner`: отдельный системный журнал не подтверждён.
  История журналов через POST на том же CGI в адаптер не включена.

Наличие адаптера означает, что программа знает способ запроса. Оно не
гарантирует наличие маршрута на конкретной прошивке. PitBit и другие семейства
пока не включены; для них доступен импорт текстового файла. Нельзя определять
совместимость только по имени модели: требуется `ProfileId` сканера.

## Контракт и ограничения

- `supported_log_kinds(row)` возвращает известные виды лога для семейства.
- `read_device_log(row, kind, access_profiles=..., cancel=...)` возвращает
  `DeviceLogResult`: `status`, `text`, `source`, `collected_at`, `kind`,
  `truncated`.
- `collected_at` — UTC-время получения текста на ПК. Время внутри строк лога
  остаётся временем устройства; синхронизация часов не предполагается.
- Для Stock/VNish/Elphapex тайм-аут всей операции, включая перебор подходящих профилей,
  — 20 секунд; размер ответа — до 2 МиБ. Превышение размера возвращает
  `too_large` без частичного текста. Отмена передаётся через `threading.Event`.
- Для WhatsMiner общий срок загрузки и разбора — 60 секунд, начальный JSON —
  до 64 КиБ, сжатый архив — до 32 МиБ, распакованный TAR — до 128 МиБ и
  512 записей. Во время ожидания данных отмена проверяется с интервалом до
  0,5 секунды. Архив обрабатывается в памяти; предел 2 МиБ для текста не является
  пределом памяти всей операции.
- Из WhatsMiner-архива выбирается только запрошенный текущий `miner-state.log`
  или `system.log` в корне либо в каталоге `<device>.logs`. Если файл больше
  2 МиБ, возвращается его конец с последними строками и `truncated=True`.
  Пустой текущий файл считается успешным чтением; отсутствие подходящего файла
  возвращает `unsupported`. Конфигурация, другие файлы и вложенные исторические
  архивы не используются как текст журнала.
- Разбор WhatsMiner-архива не создаёт файлов на диске. Ссылки и специальные
  файлы не читаются как журналы; небезопасные пути, дубли подходящего журнала,
  расширенные PAX/GNU-заголовки, sparse-файлы, повреждение gzip/TAR и лишние
  данные отклоняются. Превышение лимитов архива возвращает `too_large`.
- Изменяющих майнинг запросов, очистки журнала, SSH-команд, произвольных URL
  и переходов по HTTP-перенаправлениям нет. POST разрешён только для создания
  сессии VNish после отказа в доступе к логу.
- Для Stock используются заданные HTTP-профили. Для VNish HTTP Basic/Digest
  не подключается. Отключённые/пустые профили не подменяются стандартными.
  Ошибка сервера или ограничения частоты не запускают перебор паролей.
- Elphapex сначала читает текущий журнал без авторизации. Только при 401/403
  используются явно настроенные профили семейства `elphapex`, с сохранением
  выбранного Basic/Digest и приоритета конкретных IP/подсетей. Пароли Antminer
  не наследуются; пустые или отключённые профили не подменяются стандартными.
  Резервный LuCI-маршрут проверяется только при 404/405/501, но не при отказе
  в доступе, ошибке сервера, перенаправлении или HTML вместо журнала.
- WhatsMiner-чтение не передаёт логин, пароль или токен и не изменяет API Write
  Switch. Ответ с кодом `-2` возвращает `unsupported`, `-4` — `auth_required`;
  другие ненулевые коды — `unavailable`. При отказе архив не загружается,
  повторные запросы и подбор учётных данных не выполняются.
- HTML-страница входа, JSON-ошибка или двоичный ответ не считаются логом.
  Текст никогда не исполняется и не рендерится как HTML.
- `load_log_file(path)` импортирует текст UTF-8 и UTF-16 с BOM, до 2 МиБ;
  `source` содержит только имя файла. UTF-8 с отдельными повреждёнными байтами
  допускается с символом замены. Произвольные ANSI-кодировки не угадываются.
- Исходный текст в памяти может содержать чувствительные данные. Очистка
  перед экспортом выполняется отдельно, а исключения транспорта не выводятся
  в результат (они могут содержать пароль/токен).

Офлайн-проверки:

```shell
python -m unittest tests.test_device_logs tests.test_whatsminer_device_logs tests.test_whatsminer_log_archive tests.test_elphapex_device_logs -v
```

WhatsMiner-тесты используют искусственные ответы сокета и архивы: проверяют
фрагментацию, отмену, тайм-ауты, коды отказа, лимиты, целостность и выбор текущего
журнала. Реальные ASIC для этих тестов не нужны.
