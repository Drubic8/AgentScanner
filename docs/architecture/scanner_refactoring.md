# Рефакторинг miner_scanner

Дата: 16.09.2026. Этот документ описывает выполненные изменения ядра, а не подтверждает выполнение всего [ТЗ](../technical_specification.md).

## Что изменено

| Модуль | Ответственность |
|---|---|
| `models.py` | Паспорт, числовая телеметрия, учётные данные и результат команды |
| `profiles/catalog.json` | Версионируемые профили, наборы запросов, границы совместимости, дополнительные метрики и правила команд |
| `profiles/__init__.py` | Проверка профилей и положительное определение семейства по структурированным признакам |
| `transports.py` | HTTP-сессия, ограничение размеров/времени, JSON/TCP, RPC с четырёхбайтовой длиной, текстовый протокол |
| `drivers.py` | Выполнение плана чтения, вызов парсеров, сбор паспорта |
| `parsers/` | Перенесённые функции разбора ответов без сетевых запросов |
| `normalization.py` | Числа, явные единицы, отсутствующие значения, дополнительные пути метрик |
| `service.py` | Обнаружение, повторный опрос, кэш, очередь сканирования, периодический мониторинг |
| `commands.py` | Привязка к профилю, проверка цели, ограничение параллелизма, отправка и чтение результата |
| `repository.py` | SQLite: паспорта, последние снимки, журнал исходов команд |
| `runtime.py`, `ranges.py` | Отмена, общий бюджет времени, параметры и проверка IPv4-диапазонов |
| `core.py`, `handlers/` | Совместимые точки входа для существующего GUI и внешних потребителей |

Пакет пока называется `miner_scanner`: это сохраняет импорты `agent_core.py` и других потребителей. Перенос в `src/asic_monitor` из целевого ТЗ не требуется для использования новых границ модулей и оставлен на общий этап реорганизации приложения. Старые словари ошибок сохранены. Модуль `whatsminer_interface.py` оставлен для совместимости и не используется новым диспетчером; вывод параметров авторизации из него удалён.

## Работа сканера

1. Первый опрос собирает признаки чтением API, выбирает профиль и выполняет его план.
2. Повторный опрос обращается напрямую по сохранённому профилю. Статические сведения и недоступные дополнительные источники кэшируются на 300 секунд.
3. Данные, содержащие состояние майнинга, не относятся к статическим: конфигурация режима Bitmain/Elphapex и `get.device.info` Whatsminer обновляются при опросе.
4. Паспорт хранится в памяти и SQLite; после перезапуска снимок считается устаревшим до нового чтения.
5. Изменение профиля или противоречивые признаки не разрешают запись на основании старой привязки.
6. Сканирование выдаёт результаты по готовности и держит в очереди не более установленного числа задач. Диапазоны объединяются до запуска сети.

Начальные параметры: 64 рабочих потока, 1 с на подключение, 2 с на чтение, 15 с на операцию с устройством, до 4096 уникальных адресов. Отмена кооперативная: прекращает новые обращения; текущий блокирующий вызов завершается по своему таймауту. Глобальная подмена `socket.socket` удалена.

`ScannerService.monitor()` реализует циклы без накопления и наложения. Текущий GUI сохраняет ручной сценарий поиска; отдельная панель непрерывного мониторинга пока не добавлена.

## Управление и доступ

Для первой настройки доступа откройте **Файл → Доступ к ASIC (на текущий сеанс)** без выделенных устройств. Эти данные используются для обнаружения закрытых API. При выделенных устройствах тот же диалог назначает индивидуальные данные, имеющие приоритет. Пароли не сохраняются на диск.

Команда использует сохранённый `device_id` и заново проверяет паспорт. Производитель не извлекается из текста таблицы. Для одного IP запись и опрос синхронизированы; одновременно выполняется не более восьми управляющих операций. Управляющий запрос не повторяется автоматически.

Профили в каталоге перенесены из существующего кода и документов, **не сертифицированы на реальном оборудовании**. Поэтому их `verified_commands` пусты. Обычный режим не выполняет неподтверждённые команды.

Для аппаратного испытания перенесённой команды предусмотрен явный переключатель в диалоге доступа к выделенным устройствам. Он действует только для выбранных паспортов и текущего сеанса. Он не добавляет неизвестные команды и не включает Low/HEM без реализации профиля. При смене устройства/прошивки команда всё равно блокируется до обновления выбора.

Наличие HTTP 200 не даёт итог `succeeded`. Для режимов выполняется чтение состояния. При неоднозначном исходе возвращается `unconfirmed`. Перезагрузка и LED без обратного чтения пока возвращают подтверждение приёма с неподтверждённым фактическим состоянием. Avalon предлагает отдельное переключение LED; его запуск майнинга использует перезагрузку, о чём GUI сообщает перед выполнением.

Для новых проверенных прошивок предусмотрены декларативные `command_rules`, включая Low/HEM, с точным payload и чтением результата. Синтетический тест добавляет режим без изменений диспетчера и GUI. Реальное соответствие режима HEM конкретному значению API нельзя определить без документации/ответов оборудования.

## Данные и совместимость

SQLite по умолчанию находится в `%LOCALAPPDATA%/ASICMonitor/devices.sqlite3` на Windows. Переменная `MINER_SCANNER_DATA_DIR` переопределяет каталог. Тесты используют собственные базы, не базу приложения. Неизвестная версия схемы БД отклоняется.

Сохраняются паспорта, снимки и результаты команд; сырые конфигурации с паролями не записываются. У команды есть ID; завершённый или неопределённый исход с тем же ID не запускается повторно при последовательном обращении. Журнал очищается по сроку 30 дней.

Сохраняются прежние ключи результата `IP`, `Make`, `Model`, `Real`, `Avg`, `Temp` и другие. Добавлены `DeviceId`, `ProfileId`, `Firmware`, `FirmwareVersion`, `Identity`, `Telemetry`, `Capabilities`, `RequestCount`, `Stale`. Числовые значения находятся в `Telemetry`; прежние строки — адаптер для таблицы. Неизвестный хешрейт показывается как `—`.

Для полей `GHS` и `MHS` преобразование основано на единице поля. `hash-realtime/hash-average` Whatsminer нормализуются как TH/s согласно локальному [официальному API-справочнику](../whatsminer_official_api.md). Для неоднозначных единиц, например отдельных Equihash-прошивок, требуется явное правило `metrics`; догадка по величине числа удалена из итоговой телеметрии ядра.

## Проверки и измерения

```powershell
python scripts/check_scanner.py
python scripts/benchmark_scanner.py
python -m miner_scanner --profiles
```

На момент завершения основного рефакторинга проходят 36 проверок: диапазоны, конфликты профилей, семейства устройств, кэш, отмена, SQLite, смена прошивки, сохранность конфигурации, команды без ложного успеха, отсутствие повторной перезагрузки, фрагментированные TCP-пакеты и взаимодействие с GUI без видимого окна.

В тестах нет обращений к ASIC. Сетевой тест работает только через `127.0.0.1`; остальные используют искусственные ответы. GUI-тест запрещает внешние сетевые запросы и проверяет сохранение паспорта при сортировке.

Дополнительно проверена сборка устанавливаемого Python-пакета ядра `asic_monitor_scanner-2.0.0-py3-none-any.whl`, включая `profiles/catalog.json`. Это пакет библиотеки, а не готовый Windows EXE. Сборщик в этой Windows-песочнице потребовал отдельный чистый каталог сборки из-за прав на временные каталоги.

Измерение на 128 искусственных устройствах, 32 рабочих потока, задержка ответа 5 мс:

| Сценарий | Запросов | Запросов на устройство | Время одного прогона |
|---|---:|---:|---:|
| Первое обнаружение | 896 | 7 | 0,2884 с |
| Повторный опрос | 384 | 3 | 0,1132 с |

Это сравнение двух путей нового ядра на синтетическом стенде. Оно показывает сокращение числа запросов на 57%, но не доказывает такое же ускорение на реальных ASIC и не является сравнением со старой версией приложения.

## Что ещё требует отдельного этапа

- Аппаратная матрица моделей/версий и подтверждение каждой управляющей команды; с текущего ПК доступа к ASIC нет.
- Дополнение неизвестных единиц и особенностей API реальными обезличенными ответами. Синтетические примеры не заменяют ответы оборудования.
- Автоматическое сопоставление ASIC после смены IP, конфликты серийных номеров и полноценная история адресов. Сейчас запись ищется по адресу, а UUID сохраняется для того же подтверждённого оборудования на этом адресе.
- Проверка фактической перезагрузки по boot ID/uptime вместо текущего честного `unconfirmed`.
- Полная миграция старого GUI/экспорта на типизированные модели, постоянное защищённое хранилище паролей и история измерений. Оформление Windows и сборка EXE добавлены следующим этапом: [руководство по версии 2.0.0](../development/windows_release.md).
- Android-прототип и упаковка. Ядро не зависит от Qt/Windows UI, но Android-приложение ещё не реализовано.
- Аппаратные нагрузочные испытания и 24-часовой прогон из ТЗ не выполнялись.

Эти ограничения нельзя считать закрытыми только на основании успешного запуска автоматических тестов.
