# Canaan Avalon API Reference

**Тип API:** Avalon JSON API
**Особенность:** Скрытые данные в строках

## 1. Идентификация модели
Модель асика можно извлечь двумя путями:
1. Из блока `VERSION` -> `PROD`.
2. Из скрытого массива данных (если стандартное поле пустое).

## 2. "Секретный" блок MM ID
Avalon упаковывает часть системной информации и конфигураций внутрь длинных текстовых строк с ключом `MM ID`.
**Метод парсинга:** Используется регулярное выражение `r'(\w+)\[([^\]]*)\]'` для извлечения пар "ключ-значение" из этой строки (например, скрытые температуры или версии чипов).

## 3. Сбор метрик
* **Хешрейт:** Находится в ключах `GHS mm` (средний) и `GHS 5s` (текущий). Значение отдается в GH/s.
* **Вентиляторы:** Записаны в плоском словаре как `Fan1`, `Fan2` ... `Fan8`.
* **Температура:** Берется из `Temp`, если значений много, программа оставляет только крайние (мин/макс).

## 4. Подсветка

По [официальному руководству Canaan, раздел 2.3](https://github.com/Canaan-Creative/avalon10-docs/blob/master/Universal%20API/Avalon%20A10%20API%20manual-EN.md):

- включение: `ascset|0,led,1-1`;
- выключение: `ascset|0,led,1-0`;
- чтение состояния: `ascset|0,led,1-255`.

В проекте формат подтверждён на Avalon 1346-110, API 3.7,
сборка `24041001_08b0955_0196aba`. Перед разрешением команды выполняется
чтение состояния. Ответ должен содержать `STATUS=I`, `Code=118` и
`Msg=ASC 0 set info: LED[0]` либо `LED[1]`. После записи состояние читается снова.
Результат `succeeded` означает подтверждение API; визуальная проверка отдельная.

Сон и пробуждение различаются между сериями. Для A10 руководство описывает
отключение питания плат через `hashpower,0` и возврат перезагрузкой;
[документация Avalon Q](https://www.canaan.io/resource/api/avalon-q-commands)
описывает `softoff`/`softon` с временной меткой. Это не подтверждает тот же
формат для 1346.

## 5. Avalon 1346-110 / MM317: Sleep, Wakeup, Reboot

Запись FMS 3.3.4 от 02.10.2026 и подтверждение оператора установили:

- Sleep: `ascset|0,softoff`;
- Wakeup: `ascset|0,reboot,1` (пробуждение через перезагрузку);
- Reboot использует тот же запрос перезагрузки.

Обе записи отвечают `STATUS=S, Code=119, Msg=ASC 0 set OK`.
Это принятие запроса, не подтверждение завершения перехода.
Сканер разрешает этот контракт для `MODEL=1346-110`, `HWTYPE=MM4v1_X3`,
`SWTYPE=MM317`, API 3.7, одного модуля и соответствующей структуры телеметрии.
Дата прошивки не служит белым списком; фактическая сборка сохраняется в
идентичности устройства, и её изменение требует обновить выбор перед командой.
Другие серии не получают эти команды только потому, что у них работает LED API.

Проверка Sleep требует перехода из рабочего состояния в `In Idle`,
нулевого текущего хешрейта, отключённого питания плат и ненулевого `SoftOFF`.
Один `SoftOFF[6]` недостаточен: такой ответ наблюдался и при запуске.
Проверка Wakeup/Reboot — уменьшение времени работы после запроса.
Она подтверждает перезапуск, а не выход на номинальный хешрейт.
Проверки ограничены временем операции, потерянная запись не повторяется;
если переход не успел завершиться, результат остаётся `unconfirmed`.

См. [протокол проверки](testing/avalon-1346-2026-10-02.md).

## 6. Состояние и остаточный хешрейт после Sleep

Для подтверждённого интерфейса 1346/MM317 `SoftOFF[5]` обозначает наблюдавшееся
программное отключение. Пока питание плат или текущий хешрейт ещё не упали,
состояние отображается как `Stopping` («Засыпает»). При `In Idle`, нулевых
токе/мощности, напряжении плат 0/1 и текущем хешрейте 0 — `Sleep` («Сон»).
`SoftOFF[0]` с `In Work` и нулевым текущим хешрейтом отображается как ожидание
запуска. Один `SoftOFF[6]` остаётся неоднозначным и не даёт состояния Sleep.

Текущее значение берётся из `GHSspd` внутри `MM ID0`, затем из `GHSmm`;
нулевое значение сохраняется. `SUMMARY.MHS 1m` служит резервным источником
при отсутствии этих измерений. Оно усредняет прошлую минуту и может оставаться
положительным после отключения. Средний хешрейт за время работы сохраняется
отдельно и не используется для определения состояния.

Исправление находится в общем Python-пакете, который Android-сборка копирует
через `prepareScannerSources`. Windows показывает состояние в таблице,
фильтре и счётчиках; Android отображает переходы `stopping` / `starting`.

## 7. Официальные источники для дальнейшего развития

- [Каталог Canaan](https://www.canaan.io/support/file_download): прошивки,
  руководства и другие материалы с фильтрами по типу документа и серии.
- [Avalon Family](https://github.com/Canaan-Creative/avalon_family): согласно
  README, мобильное приложение на Flutter/Dart с Rust, Android/iOS, BLE и Wi-Fi.
  Подходит для изучения подключения и пользовательских сценариев устройств
  Avalon Home. В [документации Canaan](https://support.canaan.io/en-us/knowledgebase/article/KA-01254)
  описаны локальное управление Avalon Home и использование Avalon Family.
  Проверка README не подтверждает поддержку промышленного 1346 этим приложением.
  Лицензия репозитория — GPL-3.0; при заимствовании исходников нужно учитывать
  её условия. Наш Android-клиент использует Kotlin/Compose и общий Python-сканер.
- [fms-core](https://github.com/Canaan-Creative/fms-core): официальный Python-код
  обмена и управления Avalon, заявленный автором как пример для интеграций.
  Это более близкий источник для нашего Python-сканера; команды новых серий
  требуют проверки, как и команды из руководств для A10/Q.

Исходники сторонних проектов в приложение не добавлены. Оценка Avalon Family
здесь основана на README и официальной статье, а не на проверке всех его модулей.
