# Control Verification

Как проверять, что команда реально сработала. "HTTP 200 means success" - это плохой критерий для многих прошивок, особенно Bitmain CGI.

## Основной алгоритм для CGI-конфигов (Bitmain)

Многие прошивки возвращают `HTTP 200 OK` даже если они не приняли конфигурацию (например, если передать строку вместо числа, или пропустить обязательное поле).

**Правильная верификация (Verification Flow):**
1. Отправить конфигурацию (`POST /cgi-bin/set_miner_conf.cgi`).
2. Дождаться ответа. Если ответ не 200 - сразу считать ошибкой.
3. Если ответ 200, сделать паузу (1-2 секунды).
4. Запросить текущий конфиг заново (`GET /cgi-bin/get_miner_conf.cgi`).
5. Извлечь ключевое поле, которое мы меняли (например, `miner-mode` или `bitmain-work-mode`).
6. Сравнить текущее значение с ожидаемым (Expected Mode).
7. Если не совпадает — зафиксировать неподтверждённый результат. Не повторять запись автоматически; повторять можно чтение состояния в пределах бюджета операции.

## Правила для HTTP 200 / 404 / Empty Body

- **HTTP 200 + Ожидаемый конфиг:** Успех.
- **HTTP 200 + Старый конфиг:** Изменение не подтверждено. Причину исследуют отдельно; формат payload задаёт профиль конкретной прошивки.
- **HTTP 401/403:** Ошибка авторизации или прав. Схему входа выбирают явно; отказ не означает отсутствие функции.
- **Timeout:** Не подтверждает перезагрузку. Нужны возвращение того же устройства, уменьшение uptime и проверка восстановления майнинга. Повторный reboot автоматически не отправляется.
- **Empty Body / 404:** Зафиксировать фактический ответ. Другой endpoint допускается только через исследованный профиль, без перебора управляющих запросов.

## Выбор команды и фиксация результата

1. Проверить идентичность устройства и профиль перед изменением состояния.
2. Использовать только формат команды выбранного профиля. Если соответствие неизвестно, управление заблокировать.
3. Различать принятие запроса и подтверждение результата. Для LED требуется визуальное подтверждение, для режимов — повторное чтение и проверка работы.
4. Записать точную модель/сборку, версию приложения, исходное состояние и доказательства в [матрицу и журнал испытаний](testing/README.md).
5. Все нынешние семейные профили требуют проверки на реальном оборудовании; шаблон таблицы не устанавливает `verified_commands` автоматически.
