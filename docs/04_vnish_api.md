# VNish Firmware API Reference

**Официальная документация:** Встроенный Swagger UI (xminer-api v0.1.0)
**Оригинальный дамп:** Сохранен в `vnish_openapi.json`
**Тип API:** REST API (JSON)
**Базовый URL:** `http://{ip}/api/v1`

## 1. Авторизация (Security)
VNish использует продвинутую систему авторизации (Bearer Token / API Key), в отличие от старых Basic/Digest методов:
1. Запросить токен: `POST /api/v1/unlock`
   * **Body:** `{"pw": "your_password"}`
   * **Response:** Возвращает объект с полем `token`.
2. Использовать токен в заголовке `Authorization: Bearer <token>` для всех закрытых эндпоинтов (управление).
*Чтение статистики (GET-запросы) обычно доступно без авторизации.*

## 2. Мониторинг и Статистика (GET)
* **Инфо (`/info`):** Возвращает версию прошивки (`fw_version`), алгоритм, платформу и базовую систему.
* **Сводка (`/summary`):** Главный эндпоинт для сканера. Возвращает объект `AntmMinerStats`, который включает:
  * Статус устройства (`miner_status.miner_state`): `mining`, `initializing`, `stopped`, `failure` и др.
  * Хешрейт: `hr_realtime`, `hr_average`, `hr_stock`.
  * Платы (`chains`), Кулеры (`cooling`), Пулы (`pools`), Температуры (`chip_temp`, `pcb_temp`).

### Единицы хешрейта: аппаратная проверка L9, 28.09.2026

На Antminer L9 с VNish **1.2.6 и 1.2.7** `/info` возвращает `hr_measure: "MH/s"`.
Поля `/summary → miner.hr_realtime` и `hr_average` необходимо интерпретировать
именно в этих единицах: `17000 MH/s = 17 GH/s`. Поля совместимого CGMiner API
на этих устройствах нельзя использовать как надёжное указание масштаба по имени
`GHS`. Сканер использует REST и явно переводит исходные единицы в H/s.

Устаревшие `instant_hashrate` и `average_hashrate` имеют другой масштаб и не
используются как замена. Если REST-значение или единица отсутствуют, показывается
отсутствие данных; масштаб не подбирается по величине числа. Встроенная документация
обеих версий: `/docs/api-doc.json`, схемы `InfoJson`, `HrMeasure`, `AntmMinerStats`.

Минимальные обезличенные ответы сохранены в `tests/fixtures/vnish_l9_hardware.json`.
После исправления реальные опросы показали 17,08 GH/s (1.2.7) и 17,12 GH/s (1.2.6).
Это моментальные показания разных устройств, а не сравнительный тест прошивок.

## 3. Управление майнером (POST)
Для этих команд требуется авторизация (токен):

* **Поиск асика (Лампочка):** `/find-miner`
  * Payload: `{"on": true}` или `{"on": false}`
* **Управление майнингом (Сон / Пробуждение):** * Уснуть: `/mining/stop` (или `/mining/pause`)
  * Проснуться: `/mining/start` (или `/mining/resume`)
* **Смена пулов:** `/mining/switch-pool`
  * Payload: `{"pool_id": 1}`
* **Перезагрузка:** `/system/reboot`

### Авторизация и границы подтверждения

Bearer-токен должен иметь приоритет над Basic/Digest, выбранным для HTTP-сеанса.
Иначе requests может заменить явный заголовок Authorization на Basic или добавить
обработчик Digest. В транспорте явный Bearer/API-key теперь отключает наследование
Basic/Digest только для текущего запроса; последующие обычные запросы сохраняют
настройку сеанса. Проверка состояния после команды также передаёт Bearer-токен.

На обеих версиях подтверждены получение токена и чтение защищённого `/settings`
через исправленный транспорт с Basic и Digest в настройках сеанса. Пароль и токен
не добавлены в исходники или фикстуры. В первоначальном прогоне чтения управляющие
команды не отправлялись. В последующем отдельном испытании на L9 / 1.2.7 проверены
остановка, запуск, перезагрузка и состояния LED по API —
[протокол](testing/vnish-l9-2026-09-28.md). Визуальная проверка LED ожидается.
HTTP-пути команд сверены
со встроенной OpenAPI; payload `{ "on": true/false }` для подсветки дополнительно
сверен с JavaScript веб-интерфейса 1.2.6, поскольку requestBody отсутствует в OpenAPI.

В GUI для проверки управления отметьте нужное устройство и настройте доступ на
текущий сеанс. VNish использует пароль; поле логина в текущем общем диалоге
обязательно, но в `/unlock` не передаётся. Непроверенные на оборудовании команды
по-прежнему требуют включения соответствующей опции для выбранного устройства.
Наличие документации и успешная авторизация не заменяют аппаратную приёмку команд.
Для проверки подсветки используется GET `/status`, boolean-поле `find_miner`.

Проверка изменений: **94 автоматических теста успешно**; опубликованный EXE не
пересобирался. Для GUI из исходников требуется перезапуск и новый опрос.

## 4. Определение статуса (MinerState)
Прошивка сама отдает точный статус в поле `miner_state`. Варианты:
* `mining` — Штатная работа.
* `initializing`, `starting`, `auto-tuning` — Прогрев / Настройка (WaitWork).
* `stopped` — Принудительно остановлен (Sleep).
* `failure` — Аппаратная ошибка (Error).
* `shutting-down`, `restarting` — Перезагрузка.
