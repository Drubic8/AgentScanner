# Сообщения об уязвимостях

Исправления безопасности в первую очередь выпускаются для последней версии. Старые релизы сохраняются для истории; отдельного срока поддержки для них нет.

Если проблема раскрывает пароли, токены или позволяет управлять чужим устройством, не публикуйте технические детали в открытом Issue. Используйте **Security → Report a vulnerability**, если приватные сообщения доступны в репозитории. Если этот пункт недоступен, создайте Issue с просьбой предоставить приватный канал, без описания способа эксплуатации и секретных данных.

В приватном сообщении укажите версию программы, затронутый компонент, минимальные шаги воспроизведения на тестовом окружении и ожидаемые последствия. Удалите реальные IP, логины, пароли, кошельки и персональные данные из вложений.

Проверяйте проблему только на своих устройствах или выделенном тестовом стенде с разрешения владельца. Не запускайте испытания управляющих команд на рабочей площадке без согласования.

Срок ответа и вознаграждение не гарантируются. При исправлении подтверждённой проблемы сведения о затронутых версиях публикуются в описании выпуска.
