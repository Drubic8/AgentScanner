# ASIC Monitor для Android

Текущая Android-версия: **2.2.1** (тестовый выпуск). Интерфейс Kotlin / Jetpack Compose,
ядро Python `miner_scanner` встроено через Chaquopy. ПК и облачный сервер для сканирования не нужны.
Это тестовый выпуск; испытания на реальных ASIC пока не выполнены.
Компактный режим, групповое управление и обновления общего ядра включены в 2.2.0.

## Возможности

- Сохранение, редактирование и выбор нескольких сетей.
- IPv4, CIDR и интервалы, до 4096 уникальных IP в одном запуске.
- Сканирование, отмена, прогресс, поиск по IP, модели и прошивке.
- Карточки устройств: идентификатор, хешрейт, температура, время получения и устаревшие данные.
- Компактный список и карточки; выбранный вид сохраняется между запусками.
- Выбор устройств галочками и управление группой, журнал результата по каждому IP.
- Логин и пароль в памяти сеанса, Basic/Digest, ограничение параллелизма 4/8/16/32.
- CSV через системный выбор файла; без разрешения на доступ ко всему хранилищу.
- Управление через подтверждённые правила общего ядра, с подтверждением пользователя и без повторной отправки.
  Доступность зависит от распознанного интерфейса и правил совместимости общего ядра. Аппаратные проверки Windows не заменяют испытания на телефоне.
  Экспериментальный обход блокировки на Android не предусмотрен.
- Сон/пробуждение, подсветка и перезагрузка; Low Power, обычный режим питания и HEM
  появляются только у устройств с подтверждённой поддержкой соответствующего API.
  Совместимые интерфейсы работают без привязки только к дате прошивки.

### Управление с телефона

Нажмите на устройство, чтобы открыть подробности и команды. Для группы отметьте устройства
галочками или общим флажком над списком (выбираются результаты текущего поиска), затем «Команды».
Перед отправкой показано количество совместимых устройств; остальные будут пропущены с пояснением
в журнале. Одновременно обрабатываются максимум четыре ASIC. Отмена останавливает новые отправки;
уже отправленная команда не повторяется. После команды приложение обновляет данные чтением API,
но не ожидает полного разгона. У проверенного промышленного Avalon пробуждение выполняется через
перезагрузку — это отдельно указано перед подтверждением.

Логин и пароль из настроек применяются и при сканировании, и при отправке команды. Устройства
с разными нестандартными паролями проверяйте отдельными группами, меняя учётные данные сеанса.
При пустых полях используются стандартные профили общего ядра: Antminer `root/root`,
VNish `admin`/`root`, WhatsMiner API `super/super`. Открытый порт не отменяет требования
авторизации и разрешения API Write на ASIC.

Операция останавливается при уходе приложения в фон и потере выбранной сети. Отмена ожидает завершения
текущих сетевых запросов в пределах их таймаутов. Возобновления и фонового сервиса нет.
Сети сохраняются; список результатов находится в памяти и не восстанавливается после завершения процесса.
Общее ядро отдельно сохраняет паспорта устройств в приватной SQLite для повторной идентификации.

## Получение APK без установки инструментов

Откройте [Actions → Android APK](https://github.com/Drubic8/AgentScanner/actions/workflows/android.yml).
После успешной сборки скачайте артефакт **ASIC-Monitor-Android** (нужен вход в GitHub),
распакуйте ZIP и перенесите APK на телефон. В архиве также есть `SHA256SUMS.txt`.

Требования: **Android 7.0+**, **64-битная ОС ARM64**; x86_64 включён для эмулятора.
32-битные устройства не поддерживаются. Подключите телефон к Wi-Fi сети ASIC, Ethernet или VPN.
Сам по себе мобильный интернет доступа к локальным IP оборудования не даёт.
На время операции приложение привязывает соединения к выбранной Wi-Fi/Ethernet/VPN-сети;
Wi-Fi без интернета подходит даже при включённых мобильных данных. Активный VPN имеет приоритет.
На телефоне разрешите установку APK выбранному файловому менеджеру, затем откройте файл.

Сборка `debug` предназначена для испытаний. Ключ подписи CI временный: последующий APK может потребовать
удалить предыдущий, при этом сохранённые сети будут потеряны. Для регулярных обновлений и магазина
нужны отдельный постоянный ключ владельца, release-сборка и испытания. Ключи в Git не добавлять.

Готовый тестовый APK также публикуется в [релизе 2.2.1](https://github.com/Drubic8/AgentScanner/releases/tag/v2.2.1).
Общий выпуск Windows/APK запускается тегом `v<версия>`: публикация происходит только
после успешных проверок обеих сборок. Для следующего выпуска обновляйте версии GUI,
Python-пакета, `version.json`, Android `versionName` и увеличивайте `versionCode`.

## Локальная сборка на Windows

1. Установите [Android Studio](https://developer.android.com/studio).
2. В SDK Manager установите Android SDK Platform **36**, SDK Build-Tools **35.0.0** и Platform-Tools.
3. Выберите Gradle JDK **17** (или совместимый JDK 21). Имеющийся JDK 25 не подходит для Gradle 8.13.
4. Установите Python **3.13** с launcher `py`; проверьте `py -3.13 --version`.
5. Откройте в Android Studio именно `apps/android`, дождитесь синхронизации.
6. Запустите на USB-телефоне с отладкой либо выполните из этой папки:

```powershell
.\gradlew.bat :app:assembleDebug
```

Результат: `app/build/outputs/apk/debug/app-debug.apk`.
Gradle загрузится автоматически через wrapper с проверкой SHA256. Отдельно устанавливать Gradle или NDK не нужно.
Пути к SDK записываются IDE в локальный `local.properties`, который игнорируется Git.

## Проверка

Из корня репозитория: `python -m unittest tests.test_android_bridge -v`.
Из Android-проекта с подключённым эмулятором: `./gradlew :app:connectedDebugAndroidTest`.
CI проверяет общий сканер, Python-границу, сборку, Android Lint и запуск на эмуляторе API 35.
Эмулятор проверяет упакованный каталог профилей, SQLite, CSV, loopback TCP, HTTP Basic/Digest
(включая неверный пароль) и сохранение сети в интерфейсе. Снимки экранов доступны в артефакте отчётов.
Это не заменяет проверку доступа к реальным ASIC, HTTP-аутентификации каждой прошивки и команд на телефоне.

## Архитектура и ограничения

`MonitorViewModel.kt` управляет жизненным циклом, сетевыми событиями и состоянием интерфейса.
`android_bridge.py` задаёт контракт JSON и запускает общее ядро в рабочем потоке.
Gradle копирует только `.py` и каталог профилей из `miner_scanner` в генерируемый каталог сборки.
Дублировать правила прошивок в Android-коде не нужно. Desktop/Qt, cloud_platform и локальные секреты в APK не входят.

`DevicesScreen.kt` отвечает за список и выбор устройств; `DeviceControls.kt` — за команды,
подтверждение и журнал. Android использует `capabilities` общего ядра, а исполнитель повторно
проверяет идентификатор и API перед записью. Правила конкретных прошивок остаются в `miner_scanner`.

[Avalon Family](https://github.com/Canaan-Creative/avalon_family) полезен как справочник для
Nano / Mini / Avalon Q: [константы протокола](https://github.com/Canaan-Creative/avalon_family/blob/main/lib/common/values/machine_constants.dart)
содержат TCP-команды на порту 4028, а поиск использует UDP 10001. Эти команды нельзя автоматически
распространять на все промышленные модели Avalon. Для 1346 используется наш отдельный проверенный контракт;
код стороннего приложения в APK не включён.

`minSdk=24`, `targetSdk=36`. Перед переходом на target 37 требуется обработка runtime-разрешения
`ACCESS_LOCAL_NETWORK`. HTTPS проверяет сертификаты; для API ASIC по HTTP разрешён cleartext.
Пароли не сохраняются в SharedPreferences, Android saved state, CSV или диагностические сообщения приложения.
Протоколы конкретных ASIC могут передавать данные без шифрования; используйте доверенную сеть/VPN.
Резервное копирование данных приложения выключено.

PDF/XLSX, диагностические ZIP, непрерывный мониторинг и облачная авторизация
не входят в первую Android-альфу. План приёмки: [Android acceptance](../../docs/testing/android_acceptance.md).

## Новое в 2.2.1

Общая иконка с Windows: адаптивный значок и одноцветный вариант для Android 13+.
Русский и английский языки всего интерфейса. Выбор: **Настройки → Язык интерфейса**;

## Новое в 2.2.0

Папки сетей: укажите путь при редактировании, например `Площадка 1/Сон`; можно свернуть ветку или выбрать все её сети. Старые сети сохраняются без папки.

В списке доступны LED, Real/Avg Hash, ошибки и фильтры по модели, прошивке и состоянию. Журнал сохраняет до 1000 результатов за сеанс и экспортирует CSV через системный выбор файла.

Команды используют общий диспетчер Windows с параллельной отправкой и отдельной проверкой результата. APK остаётся тестовым: сведения о подписи и проверках — в [release notes](../../docs/releases/2.2.0.md).
